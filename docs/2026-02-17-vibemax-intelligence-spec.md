# Extension Design Outline (Proposed)

## 1. Extension Identity

*   **Name:** `vibemax-intelligence`
*   **Location:** `.pi/extensions/vibemax-intelligence/`
*   **Entry Point:** `src/index.ts`
*   **Capabilities:**
    *   **Local Knowledge Base:** Query and read the statically scraped Cycling '74 documentation (User Guide, API Reference, Learn) stored as Markdown.
    *   **Object Research:** Query Context7 *exclusively* for specific Max/MSP object references (e.g., `cycle~`, `jit.world`).
    *   **Augmentation:** Write object metadata to the local `maxpylang` database.

## 2. Environment

*   **Required Variable:** `CONTEXT7_API_KEY`
    *   **Source:** Loaded from the agent's environment or `.env` file.
    *   **Usage:** Authenticates requests to the Context7 documentation service for specific object reference queries.

## 3. Lifecycle Management

*   **Activation (`activate`):**
    *   **Knowledge Base Initialization:** Load the `knowledge-map.json` generated by `cyclescraper` into memory.
    *   **Cache Initialization:** Ensure the local cache directory `.pi/cache/vibemax-intelligence/` exists for Context7 responses.

## 4. Core Components

### A. Knowledge Base Manager (`src/kb.ts`)
*   **Asset:** `data/knowledge-map.json` and `data/content/` (Generated by `cyclescraper`).
*   **Purpose:** Serves as the primary source of truth for architectural, conceptual, and API (JS/Node/LOM) documentation.
*   **Logic:** 
    *   Loads and traverses the hierarchical `knowledge-map.json`.
    *   Provides search capabilities over node titles, descriptions, and metadata.
    *   Retrieves and serves the formatted Markdown content from the file system.

### B. Context7 Client (`src/client.ts`)
*   **Export:** `Context7Client` (Class)
*   **Scope:** Strictly limited to **Object Reference** queries.
*   **Library ID:** `/websites/cycling74` (Verified).
*   **Base URL:** `https://context7.com/api/v2/`
*   **Authentication:** Header `Authorization: Bearer <CONTEXT7_API_KEY>`
*   **Primary Method:** `getContext(query: string)`
    *   **Endpoint:** `GET /context`
    *   **Params:** `libraryId=/websites/cycling74`, `query=<object_name>`, `type=json`

### C. Cache Manager (`src/cache.ts`)
*   **Directory:** `.pi/cache/vibemax-intelligence/`.
*   **Scope:** Caches Context7 object reference responses to reduce network calls.
*   **Key Strategy:** MD5 Hash of the normalized query string (e.g., `md5("object:poly~")`).

### D. Augmenter (`src/augmenter.ts`)
*   **Dependency:** Receives an instance of `Context7Client`.
*   **Data Source:** Calls `Context7Client.getContext(object_name)` to retrieve the raw JSON for an object.
*   **Logic:**
    1.  Fetch raw data from Context7.
    2.  Transform JSON into the `maxpylang` schema (inlets, outlets, messages).
    3.  Write to `apps/maxpatcher/engine/maxpylang/data/OBJ_INFO/{category}/{object_name}.json`.   

## 5. Tools (Agent API)

### A. `search_knowledge_base(query: string) -> JSON`
*   **Description:** Searches the local scraped documentation index (`knowledge-map.json`).
*   **Behavior:** Matches the query against node titles, descriptions, and tags. Returns a list of relevant nodes with their logical paths or file paths.

### B. `read_concept(filepath: string) -> String`
*   **Description:** Reads a specific scraped Markdown article, tutorial, or API page.
*   **Arguments:** `filepath` obtained from `search_knowledge_base` or browsing the map.
*   **Returns:** Clean Markdown content containing guides, API specifications, or code examples.

### C. `research_object(object_name: string) -> JSON`
*   **Description:** Queries the Context7 API for detailed specifications of a *specific* Max/MSP/Jitter object (e.g., `coll`, `dict`).
*   **Behavior:** Returns structured JSON containing object description, arguments, attributes, inlets, and outlets. Checks local cache first.

### D. `augment_max_db(object_name: string, category: string) -> String`
*   **Description:** Writes object metadata to the local `maxpylang` database.
*   **Process:** Calls `research_object(object_name)` internally, parses the JSON, and writes to `apps/maxpatcher/engine/maxpylang/data/OBJ_INFO/{category}/{object_name}.json`.

### E. `get_navigation(path?: string, filter?: Record<string, string>) -> JSON`
*   **Description:** Returns the documentation hierarchy from the `knowledge-map.json` to allow the agent to browse the documentation structure.
*   **Arguments:**
    *   `path`: The semantic path (e.g., `User Guide/Audio`).
    *   `filter`: Optional filter matching node properties (e.g., `{ "kind": "api-index" }`).

## 6. Skill Integration (`SKILL.md`)

*   **Goal:** Enable "Research-First Development" by mapping user intent to the correct intelligence source (Scraped Knowledge Base vs. Context7 Object Reference).

### A. Documentation Router (Decision Tree)
Before researching, determine the *type* of knowledge required:
1.  **Technical Verification (Specific Objects):** Need input/output specs for a specific object (e.g., `poly~`)? -> **Use `research_object` (Context7)**.
2.  **Conceptual Understanding:** Need to understand a system (e.g., "How MC works")? -> **Use `search_knowledge_base` & `read_concept` (Local Data)**.
3.  **Scripting & Control:** Need JS API, Node for Max, or Live Object Model details? -> **Use `search_knowledge_base` & `read_concept` (Local Data)**.
4.  **Workflow Patterns:** Need a tutorial or recipe? -> **Use `search_knowledge_base` & `read_concept` (Local Data)**.

### B. Workflow: Object Reference (Technical Verification)
*   **Trigger:** You have a specific object name and need to validate it for a patch.
*   **Tool:** `research_object(object_name)`
*   **Required Extraction:**
    1.  **Description:** What does the object strictly do?
    2.  **Arguments:** What creation arguments are required vs. optional?
    3.  **Attributes:** What properties can be set?
    4.  **Inlets & Messages:** What specific messages does each inlet accept?
    5.  **Outlets:** What data/signal comes out?
    6.  **Related Objects:** Alternatives in "See Also".
*   **Verification Step:** *Before* adding the object to a plan, ask: "Do the inlets/outlets match my signal flow requirements?" If the object lacks a required inlet/message, you MUST find an alternative from the "Related Objects" list.

### C. Workflow: Discovery & Search (Concepts, APIs, Tutorials)
*   **Goal:** Move from fuzzy intent to specific documentation pages using the local knowledge base, and build a correct mental model of the subsystem to act as a **Senior Systems Architect**.
1.  **Browse Hierarchy:** Use `get_navigation(path, filter)` to explore the `knowledge-map.json` categories (e.g., `User Guide/Audio`).
2.  **Search:** Use `search_knowledge_base(query)` to find relevant articles by keyword.
3.  **Read Deeply:** Use `read_concept(filepath)` to extract architectural rules, API signatures, or code examples. When reading Conceptual/Architectural guides, you MUST extract:
    *   **Data Flow:** How do signals/messages move? (e.g., Right-to-Left order, Scheduler vs Audio thread).
    *   **State Management:** Where is state stored? (e.g., `pattr`, `dict`, object attributes).
    *   **Idioms:** What is the "Max way" to do this? (e.g., using `trigger` to ensure execution order).
    *   **Constraints:** What are the hard limits? (e.g., "Gen~ cannot allocate memory dynamically").
*   **Outcome:** A high-level **Design Strategy** that respects these constraints, formulated *before* selecting specific objects for the patch.

## 7. User Interface (TUI)
*   **Context:** Tools utilize the `ExtensionContext` (`ctx`) provided by the Pi harness.
*   **Notifications:** Use `ctx.ui.notify` to report successful cache hits, DB writes, or Context7 fetches.
*   **Progress Indicators:** Use `ctx.ui.setWorkingMessage` during active network requests to Context7.

## 8. Error Handling
*   **Context7 Errors:** 401 (Unauthorized), 429 (Rate Limit), 500 (Server Error) map to TUI notifications and retries.
*   **Local Data Errors:** If `knowledge-map.json` or a Markdown file is missing, notify the user that the `cyclescraper` data needs to be regenerated or updated.
*   **File System Errors:** Report path/permission issues if `augment_max_db` fails.

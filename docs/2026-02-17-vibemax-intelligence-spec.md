# Vibemax Intelligence Architecture Spec

## Overview
To fulfill the "Competent Co-Architect" vision, the intelligence capability of the agent is divided into three distinct, decoupled components. This architecture avoids over-engineering Pi extensions, adheres to the principle of using the simplest tool for the job, and cleanly separates concerns:

1.  **Local Knowledge Base (Skill + CLI Helper):** For conceptual understanding, RAG, and reading guides.
2.  **Context7 Extension (Pi Extension):** For precise, authenticated, and cached lookups of strict Max/MSP object specifications.
3.  **MaxDB Augmenter (Python Script):** For persisting object definitions into the `maxpatcher` runtime database.

---

## Part 1: Local Knowledge Base (RAG & Concepts)
Instead of forcing local file reads into a TypeScript extension, we leverage standard bash tools combined with a dedicated Pi Skill to navigate the output generated by `cyclescraper`.

### 1. The Skill: `vibemax-architect`
*   **Location:** `.pi/skills/vibemax-architect/SKILL.md`
*   **Purpose:** Instructs the agent on *how* and *when* to use the knowledge base to validate architectural decisions *before* writing or proposing Max/MSP code.
*   **Core Instructions:**
    *   **Workflow:** Mandates searching for and reading relevant conceptual guides and tutorials from `data/content/` to understand constraints and idioms before designing a system.
    *   **Tool Usage:** Instructs the agent to use `search_docs.py` to find relevant files, and standard Pi tools (`read`) to consume the Markdown content.
    *   **Verification:** Mandates searching the local `maxpylang` object library first (by looking for specific object filenames in `apps/maxpatcher/engine/maxpylang/data/OBJ_INFO/`, e.g., using `find` rather than a full directory `ls`). If the object is not found or lacks sufficient detail, the agent must then fallback to using the `research_max_object` extension tool (Part 2) to verify specific object mechanics (inlets, outlets, attributes).

### 2. The Search Helper: `search_docs.py`
*   **Location:** `apps/cyclescraper/search_docs.py`
*   **Purpose:** A simple CLI script the agent can invoke via `bash` to search the unified `data/knowledge-map.json`.
*   **Behavior:** 
    *   Accepts keywords or phrases.
    *   Searches node titles, descriptions, and tags within the JSON map.
    *   Returns a formatted, concise list of relevant Markdown file paths located in `data/content/` for the agent to subsequently `read`.
*   **Rationale:** Searching a large JSON file locally is a classic scripting task perfectly suited for a Python CLI, keeping the Pi extension environment lean.

## Part 2: Context7 API (Pi Extension)
A dedicated Pi Extension handling authenticated network requests to the Context7 API, providing the agent with an explicit tool for technical object verification.

### 1. Extension Identity
*   **Name:** `vibemax-intelligence`
*   **Location:** `.pi/extensions/vibemax-intelligence/`
*   **Required Variable:** `CONTEXT7_API_KEY` (loaded from the agent's environment or `.env`).

### 2. Core Components
*   **`src/client.ts`:** Manages authenticated `GET /context` requests to `https://context7.com/api/v2/` with `libraryId=/websites/cycling74`.
*   **`src/cache.ts`:** Implements file-based caching (e.g., in `.pi/cache/vibemax-intelligence/`) using MD5 hashes of queries to minimize API calls, reduce latency, and save tokens.

### 3. Agent Tool
*   **`research_max_object(object_name: string) -> JSON`**
    *   **Description:** Queries the Context7 API (checking the local cache first) for the detailed technical specifications of a specific Max/MSP/Jitter object (e.g., `coll`, `dict`, `poly~`).
    *   **Returns:** Structured JSON detailing the object's description, arguments, attributes, inlets, and outlets.

### 4. User Interface (TUI) & Error Handling
*   Uses `ExtensionContext.ui` for agent-facing notifications (e.g., indicating cache hits vs. network fetches).
*   Uses `setWorkingMessage` during active network requests.
*   Handles HTTP errors (401, 429, 500) gracefully, throwing descriptive errors that the agent can understand and act upon.

## Part 3: MaxDB Augmenter (Python Tool)
A standalone utility used to permanently teach the `maxpatcher` runtime about new objects based on the ground-truth data from Context7.

### 1. The Script: `augment_maxdb.py`
*   **Location:** `apps/maxpatcher/scripts/augment_maxdb.py`
*   **Purpose:** Fetches object data from Context7, translates it into the internal `maxpylang` schema, and writes it to the local `maxpatcher` database.
*   **Inputs:** Object name(s) and target category.
*   **Process:**
    1.  Fetches raw JSON for the requested object (either via its own Context7 client implementation or by having the agent pass the output from `research_max_object`).
    2.  Transforms the Context7 JSON schema into the schema required by `apps/maxpatcher/engine/maxpylang/data/OBJ_INFO/{category}/{object_name}.json`.
    3.  Writes the resulting JSON file to the correct directory within the `maxpatcher` app.
*   **Rationale:** Writing to the `maxpatcher` source tree is a build/maintenance task specific to the `maxpatcher` application. It is not a core, always-on agent capability that requires a Pi Extension tool. The agent simply executes `python apps/maxpatcher/scripts/augment_maxdb.py <obj> <category>` via the `bash` tool when necessary.

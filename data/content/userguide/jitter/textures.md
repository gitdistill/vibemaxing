# Textures
A **Texture** is a collection of data, organized as an array of pixel data and stored in texture memory on the GPU. Textures commonly hold image data—they have the name "texture" because they're often applied to the surface of a 3D model to change its appearance. However, a texture can hold any kind of data that can be expressed as an array of numbers.
![](https://docs.cycling74.com/images/d86a7574a7e321322ca2d0aa69412c53_752.webp) An image of chili peppers, mapped as a texture onto the surface of a sphere
Because textures are managed by the GPU, they can be processed much faster than the equivalent [matrix](https://docs.cycling74.com/userguide/jitter/matrix/), which is managed by the CPU. For tasks like distorting or manipulating an image, it's almost always more efficient to work with a texture than a matrix.
## Creating a Texture
The Max object for managing textures is called [jit.gl.texture](https://docs.cycling74.com/reference/jit.gl.texture "jit.gl.texture"). Similar to objects like [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") and [buffer~](https://docs.cycling74.com/reference/buffer~/ "buffer~"), every Jitter texture has a name, and objects send a message like `jit_gl_matrix u1234567` to other objects to refer to a specific texture. Like matrices, Jitter textures have a _dimension_ and a _type_. The type of a texture determines the resolution of each pixel. For example, a `char` type can have 256 different values, while a `float32` type can have millions of different values.
![](https://docs.cycling74.com/images/44e78d8c03fd08ab956d1fce1177ea86_386.webp) If a texture isn't given an explicit name, Max will assign it a unique name automatically.
### Graphics context
All textures are belong to a particular [graphics context](https://docs.cycling74.com/userguide/jitter/graphics_processing/#graphics-contexts), usually a window managed by [jit.world](https://docs.cycling74.com/reference/jit.world "jit.world"), or else a view managed by [jit.pworld](https://docs.cycling74.com/reference/jit.pworld "jit.pworld"). Use the `@drawto` attribute to explicitly assign a texture to one context or another.
![](https://docs.cycling74.com/images/2e2c2da694f15f35e851a84138fd9875_714.webp) Use @drawto to bind a jit.gl.texture to a particular graphics context.
If you don't assign [jit.gl.texture](https://docs.cycling74.com/reference/jit.gl.texture "jit.gl.texture") a value for `@drawto`, it will bind to the first graphics context that it can find. If there is more than one graphics context, it's undefined which context it will bind to. It's common to see `@drawto` omitted when there is only one graphics context.
### Loading from a video or image
You can fill a texture with an image by sending it the `read` message. After reading, the texture will store the contents of the image in memory. If you don't give the texture an explicit value for `@dim`, then the dimensions of the texture will adapt to fit the image.
![](https://docs.cycling74.com/images/f4fcc1d441fc4fafc87718987409074f_624.webp) Even though both texture objects loaded the same image, the dimensions are different because one texture does not have an explicit value for @dim.
### Adapt
When a [jit.gl.texture](https://docs.cycling74.com/reference/jit.gl.texture "jit.gl.texture") receives another texture as input, it copies that input texture. If the `@adapt` attribute is enabled, the [jit.gl.texture](https://docs.cycling74.com/reference/jit.gl.texture "jit.gl.texture") will also update its dimensions and type to match that of the input. The `@adapt` attribute defaults to active, unless an explicit value for `@dim` is set.
## Texture output
Many Jitter objects have an attribute `@output_texture` that can be enabled in order to configure them for texture output. When streaming video, either from a camera with [jit.grab](https://docs.cycling74.com/reference/jit.grab "jit.grab") or from a file with [jit.movie](https://docs.cycling74.com/reference/jit.movie "jit.movie") or [jit.playlist](https://docs.cycling74.com/reference/jit.playlist "jit.playlist"), enable `@output_texture` to stream to a texture as opposed to a matrix. Similarly, toggle `@output_texture` on a [jit.world](https://docs.cycling74.com/reference/jit.world "jit.world") object to capture the entire render output as a texture. When using [jit.gl.node](https://docs.cycling74.com/reference/jit.gl.node "jit.gl.node") to render to an [offscreen context](https://docs.cycling74.com/userguide/jitter/graphics_processing/#offscreen-contexts), use `@capture 1` instead of `@output_texture 1` to get a texture output from [jit.gl.node](https://docs.cycling74.com/reference/jit.gl.node "jit.gl.node").
![](https://docs.cycling74.com/images/c812a02b4b60ead4790f08ba143a1ede_1024.webp) Three important objects that can be configured for texture output
## Converting to a Matrix
Remember that Jitter matrices reside on the CPU, while Jitter textures are managed by the GPU. Because of this, converting an texture to a matrix or a matrix to a texture requires copying data from one processor to the other. This can take an undefined amount of time, and so Max provides both a synchronous and an asynchronous method to convert matrices to textures.
### [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix")
You can send a Jitter texture directly to a [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object. Max will read the data from the texture and store it in the matrix. This is the synchronous way of converting a texture to a matrix. It's the fastest way to get the result, but it can block other rendering commands during the data copy. If you're trying to copy a texture to a matrix during a live performance, it's usually better to use [jit.gl.asyncread](https://docs.cycling74.com/reference/jit.gl.asyncread "jit.gl.asyncread").
### [jit.gl.asyncread](https://docs.cycling74.com/reference/jit.gl.asyncread "jit.gl.asyncread")
This object uses a double-buffering technique to copy data to a matrix without blocking. Because of this, you're safe to use [jit.gl.asyncread](https://docs.cycling74.com/reference/jit.gl.asyncread "jit.gl.asyncread") as much as you want, even during other real-time rendering. However, since the process is asynchronous, you're guaranteed to incur one frame of delay durin the copy. Most of the time this doesn't matter, and it's fine to use [jit.gl.asyncread](https://docs.cycling74.com/reference/jit.gl.asyncread "jit.gl.asyncread") unless you're doing something very specific.
## Procedural Textures
In addition to loading textures from an image file, or copying them from a Jitter matrix, you can also generate texture procedurally.
### jit.gl.pix
The [jit.gl.pix](https://docs.cycling74.com/reference/jit.gl.pix "jit.gl.pix") object uses the Gen object namespace to define a pixel shader. One way to make a procedural texture is by using the [cell](https://docs.cycling74.com/reference/gen_jit_cell/ "gen_jit_cell"), [dim](https://docs.cycling74.com/reference/gen_jit_dim/ "gen_jit_dim"), [norm](https://docs.cycling74.com/reference/gen_jit_norm/ "gen_jit_norm"), and [snorm](https://docs.cycling74.com/reference/gen_jit_snorm/ "gen_jit_snorm") objects.
![](https://docs.cycling74.com/images/157a5bc4427cef2834b52b4b80f5141b_748.webp) A simple procedural shader defined with jit.gl.pix
### jit.gl.slab
The [jit.gl.slab](https://docs.cycling74.com/reference/jit.gl.slab "jit.gl.slab") object works very similarly to [jit.gl.pix](https://docs.cycling74.com/reference/jit.gl.pix "jit.gl.pix"), except it load a shader definition from a [Jitter XML Shader or JXS](https://docs.cycling74.com/userguide/jitter/jxs_file_format/) description file. Generator shaders like `gn.stripes.jxs` can use texture coordinates to fill a texture procedurally, just like you might do with [jit.gl.pix](https://docs.cycling74.com/reference/jit.gl.pix "jit.gl.pix").
## 3D Textures
Most textures have two dimensions, but Jitter supports 3D textures as well. This can be useful when generating your own textures, or when using textures to do simulations or other kinds of computation. To create a 3D texture, simply set the `@dim` attribute of a texture to be a list of three numbers, one for the size of each dimension.
![](https://docs.cycling74.com/images/2072bdaca92e0a9b1432354ed4ba1ad9_303.webp) A three-dimensional texture
When working with a 3D texture, you must set the `@rectangle` attribute to zero. This may change with a future version of Max, but it's necessary for now.
You can fill a 3D texture directly by sending it a 3D matrix. As usual when [converting from a matrix](https://docs.cycling74.com/userguide/jitter/textures/#converting-to-a-matrix), Max will simply copy the matrix to the texture. However, you can also use two-dimensional images to fill each slice of the 3D texture one-by-one. If you want to fill a 3D texture using a series of 2D matrices, use the message `subtex_matrix` in conjunction with the `@dstdimstart` and `@dstdimend` attributes. Open the example patcher [subtex.3d](c74max://patcher/subtex.3d.maxpat) for a demo.
You can also fill a 3D texture using a series of 2D textures. For this method, set the `@slice` attribute of the 3D texture object before sending it a two-dimensional texture. See the example patcher [tex3d.warpy](c74max://patcher/tex3d.warpy.maxpat) to see how this works in practice.
To pull a 2D texture slice from a 3D texture, you must use a shader program that takes a 3D texture input. The built-in [JXS](https://docs.cycling74.com/userguide/jitter/jxs_file_format/) file `td.plane3d.jxs` implements a shader program that can sample a specific slice from a 3D texture using either an `offset` parameter or with a secondary _map_ texture. Use this shader with [jit.gl.slab](https://docs.cycling74.com/reference/jit.gl.slab "jit.gl.slab") to convert a 3D to a 2D texture.
![](https://docs.cycling74.com/images/6d16d6d5fe20a880daf321ee935e89b2_676.webp)
Taking a 2D slice from a 3D texture with td.plane3d.jxs and jit.gl.slab

# MC Dynamic Routing
There are two basic methods of dynamic routing for multi-channel signals:
  * Use [mc.send~](https://docs.cycling74.com/reference/mc.send~ "mc.send~") and [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~") to send multiple channels of audio between patchers
  * Use [mc.matrix~](https://docs.cycling74.com/reference/mc.matrix~ "mc.matrix~"), [mcs.matrix~](https://docs.cycling74.com/reference/mcs.matrix~ "mcs.matrix~"), [mc.selector~](https://docs.cycling74.com/reference/mc.selector~ "mc.selector~"), and [mc.gate~](https://docs.cycling74.com/reference/mc.gate~ "mc.gate~") to control routing of multichannel signals using Max messages


## Sending Multi-Channel Audio Between Patchers
[mc.send~](https://docs.cycling74.com/reference/mc.send~ "mc.send~") and [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~") are multi-channel versions of [send~](https://docs.cycling74.com/reference/send~/ "send~") and [receive~](https://docs.cycling74.com/reference/receive~/ "receive~"). An important limitation when using these multichannel versions is that you must expicitly define the number of channels you will be communicating between the objects via a typed-in argument that follows the receive name. The [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~") cannot change its number of channels dynamically.
![](https://docs.cycling74.com/images/e7e6386073dd45ed4ffb4161fadea462_172.webp)
Any [mc.send~](https://docs.cycling74.com/reference/mc.send~ "mc.send~") objects with a matching name can send up to the defined number of channels in the [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~"). Extra channels in a multi-channel signal connected to [mc.send~](https://docs.cycling74.com/reference/mc.send~ "mc.send~") are ignored. If you supply too few channels to [mc.send~](https://docs.cycling74.com/reference/mc.send~ "mc.send~"), [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~") will output these channels as zero signals. In other words, [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~")_always_ produces a multi-channel signal with a set number of channels regardless of what you send it via [mc.send~](https://docs.cycling74.com/reference/mc.send~ "mc.send~").
## Dynamic Routing Using mc.send~ and mc.receive~
Like [send~](https://docs.cycling74.com/reference/send~/ "send~") and [receive~](https://docs.cycling74.com/reference/receive~/ "receive~"), the [mc.send~](https://docs.cycling74.com/reference/mc.send~ "mc.send~") and [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~") objects accept the `set` message to change the source or destination name they use to communicate. However, the fixed channel limitation of [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~") is tied to the object instance, not the symbol used for the destination name. Here is an example using the `set` message to [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~"). To start, the [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~") uses the name `foo` and is communicating with the four-channel [mc.send~](https://docs.cycling74.com/reference/mc.send~ "mc.send~") with name `foo`.
![](https://docs.cycling74.com/images/a730aa23a0bd504c5d9bbc91f5a59379_247.webp)
If we send `set bar` to the [mc.receive~](https://docs.cycling74.com/reference/mc.receive~ "mc.receive~"), the output is still four channels despite the fact that [mc.send~](https://docs.cycling74.com/reference/mc.send~ "mc.send~") with name `bar` is only sending two channels.
![](https://docs.cycling74.com/images/10cccfb1551340879d6e7edb8694c805_413.webp)
## Dynamic Multi-Channel Routing Using Max Messages
The [mc.gate~](https://docs.cycling74.com/reference/mc.gate~ "mc.gate~") and [mc.selector~](https://docs.cycling74.com/reference/mc.selector~ "mc.selector~") use the [MC Wrapper](https://docs.cycling74.com/userguide/mc/mc_wrapper/) and work similarly to their single-channel counterparts. The number or signal at the left inlet switches all channels of the multi-channel signal in the other inlets ([mc.selector~](https://docs.cycling74.com/reference/mc.selector~ "mc.selector~")) or outlets ([mc.gate~](https://docs.cycling74.com/reference/mc.gate~ "mc.gate~")).
![](https://docs.cycling74.com/images/3638e74483f956cf1805ffb7f3bf243f_466.webp)
The behavior of the two multichannel variants of the [matrix~](https://docs.cycling74.com/reference/matrix~/ "matrix~") warrants a more detailed explanation. The [mc.matrix~](https://docs.cycling74.com/reference/mc.matrix~ "mc.matrix~") consists of multiple [matrix~](https://docs.cycling74.com/reference/matrix~/ "matrix~") objects in the MC Wrapper. However, because each [matrix~](https://docs.cycling74.com/reference/matrix~/ "matrix~") can be individually targeted, channels within a multichannel input can be routed to different multichannel outputs. In this example, there is an [mc.matrix~](https://docs.cycling74.com/reference/mc.matrix~ "mc.matrix~") with one multichannel input and two multichannel outputs. By sending the message `0 0 1` (which goes to all [matrix~](https://docs.cycling74.com/reference/matrix~/ "matrix~") instances in the wrapper), we assign the inputs to the left outlet. The right outlet produces a multi-channel signal with zero in all channels.
![](https://docs.cycling74.com/images/fd41d255d55a02a6e195e046ae642087_431.webp)
Using the wrapper's `setvalue` message to [mc.matrix~](https://docs.cycling74.com/reference/mc.matrix~ "mc.matrix~"), we can assign only the third channel of the input multi-channel signal to the right outlet using the message `setvalue 3 0 1 1`.
![](https://docs.cycling74.com/images/533781f8e593c85362452cfaa7cdd539_436.webp)
The [matrix~](https://docs.cycling74.com/reference/matrix~/ "matrix~") object numbers its channels starting at 0 whereas [mc.target](https://docs.cycling74.com/reference/mc.target "mc.target") and the MC Wrapper `setvalue` message start channel numbering at 1. The special wrapper `setvalue` target of 0 before a message will address _all_ instances inside a wrapped object, which is the same thing as sending the message without using `setvalue`.
The [mcs.matrix~](https://docs.cycling74.com/reference/mcs.matrix~ "mcs.matrix~") object is a single [matrix~](https://docs.cycling74.com/reference/matrix~/ "matrix~") object where all the signal inputs are combined into one multichannel input and all the signal outputs are combined into one multichannel output. To duplicate the above example with [mc.matrix~](https://docs.cycling74.com/reference/mc.matrix~ "mc.matrix~") in [mcs.matrix~](https://docs.cycling74.com/reference/mcs.matrix~ "mcs.matrix~"), first observe that there are _four_ total inputs and _eight_ total outputs, despite the arguments `1 2` to [mc.matrix~](https://docs.cycling74.com/reference/mc.matrix~ "mc.matrix~"). To match this, we need an [mcs.matrix~](https://docs.cycling74.com/reference/mcs.matrix~ "mcs.matrix~") with arguments `4 8`:
![](https://docs.cycling74.com/images/bf0340df0da85a12dae04e4c7184afe6_416.webp)
Since [mcs.matrix~](https://docs.cycling74.com/reference/mcs.matrix~ "mcs.matrix~") provides only one multichannel output, we need to use an [mc.separate](https://docs.cycling74.com/reference/mc.separate "mc.separate") to split its eight-channel multichannel signal into two four-channel multichannel signals. To route the third channel of the input in the same way, we send the message `2 6 1` (remember [matrix~](https://docs.cycling74.com/reference/matrix~/ "matrix~") channels are zero-relative):
![](https://docs.cycling74.com/images/ea03c5f319fd3e0758095a2ca1a07e52_411.webp)
Generally, you'll prefer [mc.matrix](https://docs.cycling74.com/reference/mc.matrix "mc.matrix") when you want to route multichannel signals _as a whole_ to different patch cords. This can be achived in one message with the [mc.matrix](https://docs.cycling74.com/reference/mc.matrix "mc.matrix") example:
![](https://docs.cycling74.com/images/55d4d3f4524e646079b95df852595554_417.webp)
By contrast, [mcs.matrix~](https://docs.cycling74.com/reference/mcs.matrix~ "mcs.matrix~") is an effective way to manipulate channels _within_ a multichannel signal. For example, sending the messages `0 7 1, 1 6 1, 2 5 1, 3 4 1, 4 3 1, 5 2 1, 6 1 1, 7 0 1` in this [mcs.matrix~](https://docs.cycling74.com/reference/mcs.matrix~ "mcs.matrix~") reverses the order of the eight input channels.
![](https://docs.cycling74.com/images/ba8f67e44f25740b49db915404828b87_498.webp)

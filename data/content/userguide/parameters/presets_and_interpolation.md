# Presets and Interpolation
A **preset** is a set of values of one or more objects in your patcher you have stored for later recall. Max has two objects, [preset](https://docs.cycling74.com/reference/preset/ "preset") and [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage"), whose primary purpose is storing and recalling these sets of values. You can use other objects for this purpose, including [table](https://docs.cycling74.com/reference/table/ "table"), [coll](https://docs.cycling74.com/reference/coll/ "coll"), and [dict](https://docs.cycling74.com/reference/dict/ "dict"), but [preset](https://docs.cycling74.com/reference/preset/ "preset") and [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") have two principal advantages:
  * they can store and recall the state of objects without patch cord connections
  * they offer the ability to **interpolate** between two or more preset states


## Storing and Recalling Values
### The [preset](https://docs.cycling74.com/reference/preset/ "preset") Object
The [preset](https://docs.cycling74.com/reference/preset/ "preset") object is an easy-to-use way to capture the state of user interface objects. The [preset](https://docs.cycling74.com/reference/preset/ "preset") object is itself a user interface object. Each square in its grid represents a different preset.
![](https://docs.cycling74.com/images/e77d2aacac63e0a10e8cab9614926e4a_105.webp)
In the example below, shift-clicking on any square in the [preset](https://docs.cycling74.com/reference/preset/ "preset") will capture the current state of all the user interface objects in the patcher -- the dial, slider, and number box. Clicking on the square (without holding down the shift key) will recall the stored state asociated with the sequare (and draw that square to indicate it's current).
![](https://docs.cycling74.com/images/02748412a44e99ebc4a05b4bcf2a5393_274.webp)
Any preset data you store will be saved in the patcher file containing the [preset](https://docs.cycling74.com/reference/preset/ "preset") object.
### The [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") Object
The [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") object has many features and operating modes that go far beyond what [preset](https://docs.cycling74.com/reference/preset/ "preset") is capable of doing. In this brief introduction, we'll discuss how to use [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") in a manner roughly similar to [preset](https://docs.cycling74.com/reference/preset/ "preset").
The name [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") comes from its role in storing the values of [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects. "Pattr" is short for _patcher attributes_ and is an object that creates a single named storage location. While [preset](https://docs.cycling74.com/reference/preset/ "preset") stores the values of user interface objects directly, [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") needs a [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object before it will store anything. Conveniently, it's not necessary to make [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects explicitly to store the values of user interface objects. Instead, two things are required:
  * ensure each object whose value you want to store has a scripting name -- this will be true for objects such as [live.dial](https://docs.cycling74.com/reference/live.dial "live.dial") that default to [parameter mode](https://docs.cycling74.com/userguide/parameter_mode/) on but not for [toggle](https://docs.cycling74.com/reference/toggle/ "toggle"), [dial](https://docs.cycling74.com/reference/dial/ "dial") or other UI objects that do not enable parameter mode by default. (Parameter mode itself is not required to use [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage"), just the scripting name.)
  * add an [autopattr](https://docs.cycling74.com/reference/autopattr/ "autopattr") object to your patcher.


The [autopattr](https://docs.cycling74.com/reference/autopattr/ "autopattr") will ensure every user interface object with a scripting name has a hidden [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") to go with it.
![](https://docs.cycling74.com/images/419117a2608695cf5ec6e286f66f92da_357.webp)
If you double-click on the [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") object, you'll see all of the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") slots and their current values.
![](https://docs.cycling74.com/images/eb52bc70cfae2450674e48babc44e463_385.webp)
To store a preset with the current values managed by [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage"), send the message store followed by a slot number starting at 1.
Send that same number back to recall to [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") to recall the preset. (The [preset](https://docs.cycling74.com/reference/preset/ "preset") object accepts the same messages.)
To see the contents of all your presets, you can open the **storage window** by sending the message `storagewindow` to [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage").
![](https://docs.cycling74.com/images/eaa25e1b907495bc4d1f7e60a05ba1ef_457.webp)
Saving [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") data in a file offers more options than [preset](https://docs.cycling74.com/reference/preset/ "preset"). The default option is to prompt you to save any newly stored data in a separate file when you close the parent patcher. You can read this data file back into [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") using the `read` message.
## Interpolating Between Two Presets
Both [preset](https://docs.cycling74.com/reference/preset/ "preset") and [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") offer the ability to _interpolate_ between two adjacent presets. Interpolation is an operation that produces a value in between two values. In both objects, you use a float value between two storage slots to specify where in the distance between the slots you want the resulting values.
Here's a simple example with a single object. Suppose the value of a [slider](https://docs.cycling74.com/reference/slider/ "slider") for preset 1 is 0 and 1 for preset 2. An float value 1.5 sent to [preset](https://docs.cycling74.com/reference/preset/ "preset") or [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") will produce an output value halfway between the two presets, resulting in a value of 0.5 (which is half way between 0 and 1). A float value of 1.9 will produce a value closer to preset 2 than preset 1 -- in this case the [slider](https://docs.cycling74.com/reference/slider/ "slider") will be set to 0.9.
When you interpolate between two presets with the [preset object](https://docs.cycling74.com/reference/preset%20object/ "preset object"), the display of the active slot will show the relative contribution of each of the two slots. The display can help you keep in mind that a value of 1.7 does not mean preset 1 contributes 70% to the value; in fact, just the opposite. The interpolation calculation is based on the _distance_ between the value and the whole number. The farther away the float value is from the whole number, the less that preset slot will contribute to the final interpolated outcome. And the closer the float value is to a whole number, the more that preset slot will contribute. Thus 1.99 will be 99% preset 2 and 1% preset 1.
![](https://docs.cycling74.com/images/50f5bf765b6a7544575cc8897f87a14a_114.webp)
While [preset](https://docs.cycling74.com/reference/preset/ "preset") is limited to linear interpolation, [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") offers several other interpolation curves and behaviors via its `interp` message.
## Multi-Preset Interpolation
Both [preset](https://docs.cycling74.com/reference/preset/ "preset") and [pattstorage](https://docs.cycling74.com/reference/pattstorage/ "pattstorage") offer the ability to interpolate using the data in several preset slots with the `recallmulti` message. Multi-preset interpolation is based on a list of weights, where the integer part of the value is the preset slot number and the decimal part is the relative weight of the preset contributing to the outcome. Weights are normalized so they don't have to add up to 1. Here's an example using the [preset](https://docs.cycling74.com/reference/preset/ "preset") object below where we want to use preset slots 1, 4, and 7.
![](https://docs.cycling74.com/images/4804d3430032197f9e6b0a1c7c88dc60_107.webp)
`recallmulti 1.5 4.5 7.5` will weigh each preset slot equally. So will `recallmulti 1.2 4.2 7.2`. `recallmulti 1.8 4.0 7.2` will be 80% preset 1 and 20% 7, with nothiing from preset 4.
As with two-preset interpolation, the [preset](https://docs.cycling74.com/reference/preset/ "preset") object will display the weights for the most recent `recallmulti` message.
![](https://docs.cycling74.com/images/191d5c109ce68c47dc139abcb802662a_145.webp)
## Non-Interpolating User Interfaces
###  [preset](https://docs.cycling74.com/reference/preset/ "preset") As a Front End for [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage")
You can use a [preset](https://docs.cycling74.com/reference/preset/ "preset") as a front-end for storage and recall of presets in [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage"). Give [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") a name with its first argument, then set the `pattrstorage` attribute of [preset](https://docs.cycling74.com/reference/preset/ "preset") to this name. After doing this, shift-clicking on a slot in [preset](https://docs.cycling74.com/reference/preset/ "preset") actually stores a preset at the same slot in [pattstorage](https://docs.cycling74.com/reference/pattstorage/ "pattstorage"), and clicking on a slot in [preset](https://docs.cycling74.com/reference/preset/ "preset") recalls the corresponding slot in [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage").
###  [umenu](https://docs.cycling74.com/reference/umenu/ "umenu") and [chooser](https://docs.cycling74.com/reference/chooser/ "chooser") As a Front End for [preset](https://docs.cycling74.com/reference/preset/ "preset")
To display presets in a list format rather than the grid of the [preset](https://docs.cycling74.com/reference/preset/ "preset") object, connect a [umenu](https://docs.cycling74.com/reference/umenu/ "umenu") or [chooser](https://docs.cycling74.com/reference/chooser/ "chooser") to the left inlet of [preset](https://docs.cycling74.com/reference/preset/ "preset"). The contents of the [umenu](https://docs.cycling74.com/reference/umenu/ "umenu") and [chooser](https://docs.cycling74.com/reference/chooser/ "chooser") will be kept in sync with the storage state and most-recently recalled slot of [preset](https://docs.cycling74.com/reference/preset/ "preset"). You can also display names for each preset slot by appending an optional name to the `store` message. `store 2 Cyclical` will name the new preset `Cyclical`. You can see the name when moving the cursor over the stored slot in [preset](https://docs.cycling74.com/reference/preset/ "preset") or, if you have a connected [umenu](https://docs.cycling74.com/reference/umenu/ "umenu") or [chooser](https://docs.cycling74.com/reference/chooser/ "chooser") it will show up in the item text.
![](https://docs.cycling74.com/images/b79655d770f1a30ff9e98943978f4c77_403.webp)
## Interpolation User Interfaces
The [nodes](https://docs.cycling74.com/reference/nodes/ "nodes") object is ideal for multi-preset interpolation with either [preset](https://docs.cycling74.com/reference/preset/ "preset") or [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage"). Connecting [nodes](https://docs.cycling74.com/reference/nodes/ "nodes") to the inlet of [preset](https://docs.cycling74.com/reference/preset/ "preset") creates a visual "node" for each stored preset up to a maximum set by the Max Dynamic Nodes (`maxdynamicnodes`) attribute, which defaults to 8. Dragging the mouse over [nodes](https://docs.cycling74.com/reference/nodes/ "nodes") performs multi-preset interpolation.
![](https://docs.cycling74.com/images/b44d1d8573a5d7b1d1bcf3d9b9cd049d_132.webp)
Using [nodes](https://docs.cycling74.com/reference/nodes/ "nodes") with [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage") requires more work including manually creating the set of nodes that will correspond to the preset slots you want to interpolate and some patching logic to translate the values coming out of [nodes](https://docs.cycling74.com/reference/nodes/ "nodes") to the correct values for the `recallmulti` message. An example is found in the _pattrstorage_ tab of the [nodes object help file](https://docs.cycling74.com/userguide/presets_and_interpolation/openfilelink).

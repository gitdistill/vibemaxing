#  [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") Tutorial 1: Patcher Storage
## Introduction
Max has a wide variety of objects for storing and managing data. Objects such as [table](https://docs.cycling74.com/reference/table/ "table"), [funbuff](https://docs.cycling74.com/reference/funbuff/ "funbuff"), [coll](https://docs.cycling74.com/reference/coll/ "coll"), and [umenu](https://docs.cycling74.com/reference/umenu/ "umenu") all store information that you can set manually or via a mechanism within a patch itself. The [preset](https://docs.cycling74.com/reference/preset/ "preset") object, which also stores data, is useful for capturing and recalling the _states_ of user-interface objects within a patcher, giving you the ability to rapidly restore settings to multiple parts of your patch in one step.
## What is [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") ?
Often a project in Max will require a more sophisticated state management system than the basic data structures objects allow for. The [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") family of objects ([pattr](https://docs.cycling74.com/reference/pattr/ "pattr"), [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub"), [autopattr](https://docs.cycling74.com/reference/autopattr/ "autopattr"), and [pattrstorage](https://docs.cycling74.com/reference/pattrstorage/ "pattrstorage")) provides the functionality of the [preset](https://docs.cycling74.com/reference/preset/ "preset") object with a more extensive set of state management features:
  * We can maintain sets of data from objects throughout a Max patch hierarchy. For example, with [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") you can control the state of objects inside of [patcher](https://docs.cycling74.com/reference/patcher/ "patcher") and [bpatcher](https://docs.cycling74.com/reference/bpatcher/ "bpatcher") objects all from the top level of the patch.
  * We can store any type of data used by any type of object (including data simply stored inside a [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") itself, without any other objects involved).
  * We can use [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects to remotely set and query the state of objects controlled by the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") system from anywhere within the patch.
  * The [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects store groups of settings as XML files, allowing us to easily read and edit saved data outside of Max.
  * The [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects can recall the state of objects in a specific order, avoiding difficulties with, for example, the recalling of a [toggle](https://docs.cycling74.com/reference/toggle/ "toggle") object that starts a process before all the variables are in place for the process to function correctly.
  * Not only can we store the states of many objects under a single address, we can also interpolate between these states, allowing for a seamless crossfade between multiple settings.
  * The [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects feature a high-level interface for viewing and managing the current state of controlled objects and the states that have been saved.


In this tutorial, we’ll look at some of the basic features of [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") and [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub"), showing how the objects can be used to communicate remotely with objects anywhere in a Max patch.
## Object Binding
Take a look at the tutorial patcher. Turn on the [metro](https://docs.cycling74.com/reference/metro/ "metro") object with the [toggle](https://docs.cycling74.com/reference/toggle/ "toggle") object box labeled "start". You should hear some music if you double-click the [noteout](https://docs.cycling74.com/reference/noteout/ "noteout") object and select a valid output synthesizer. The number box attached to the [metro](https://docs.cycling74.com/reference/metro/ "metro") object controls the speed of the generated pattern. Click on the colored `message` boxes to the right of the patch and note that they change the value of that [number](https://docs.cycling74.com/reference/number/ "number") box even though they are not connected directly to it.
Clicking in a colored [message](https://docs.cycling74.com/reference/message/ "message") box changes the [metro](https://docs.cycling74.com/reference/metro/ "metro") object’s time value.
The [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object to the right of the [metro](https://docs.cycling74.com/reference/metro/ "metro") object is controlling the value in the [number](https://docs.cycling74.com/reference/number/ "number") box above it. In the language of patcher storage, we say that our [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object is _bound_ to the [number](https://docs.cycling74.com/reference/number/ "number") box. When we send messages to that [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object, it will at all times refer to the data stored in the [number](https://docs.cycling74.com/reference/number/ "number") box, allowing us to ask the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object what the number is currently set to, as well as tell the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object to set the number to a specific value remotely.
Our [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object has a _name_ - `speed` - which is set by the object’s argument and allows other [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") -family objects to communicate with it. The [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub") object at the bottom of the patch can receive messages and forward them to any [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects in the patch. By sending the message `speed 125` to the [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub"), we are telling the object to find the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") with the name `speed`. If it finds the relevant [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object, it will instruct the object to send the message `125` to whatever object it is bound to (in this case, our [number](https://docs.cycling74.com/reference/number/ "number") box).
Unlock the patch and click on the [number](https://docs.cycling74.com/reference/number/ "number") box attached to the [metro](https://docs.cycling74.com/reference/metro/ "metro") object. Select **Name…** from the **Object** menu. The object inspector will open showing the **Scripting Name** of the [number](https://docs.cycling74.com/reference/number/ "number") box is `temponum`.
Our [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object is bound to our [number](https://docs.cycling74.com/reference/number/ "number") box because the `bindto` attribute of our [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object is set to the name of our [number](https://docs.cycling74.com/reference/number/ "number") box (`temponum`). The act of _naming_ Max objects allows us easier access to them via the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") system. Note that the [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub") object controls our [number](https://docs.cycling74.com/reference/number/ "number") box via the name of the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object to which it is bound (`speed`), not the name of the [number](https://docs.cycling74.com/reference/number/ "number") box itself (`temponum`).
Rename the [number](https://docs.cycling74.com/reference/number/ "number") box to something else and close the Inspector. Try changing settings for the patch by clicking on the message boxes again.
Note that if we rename our referred object, our [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object can no longer bind to it. In order to rebind it, we need to tell [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") to bind to our [number](https://docs.cycling74.com/reference/number/ "number") box again.
Open the Inspector for the [number](https://docs.cycling74.com/reference/number/ "number") box and name it back to `temponum`. Close the inspector and recreate the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object binding to `temponum` (either delete the object and undo the deletion, or create a new [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object). Verify that it is receiving updates from the [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub") object by clicking on the [message](https://docs.cycling74.com/reference/message/ "message") boxes again.
Instead of recreating the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object, we could have sent our newly ‘unbound’ [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object a `bindto` message with the name of the [number](https://docs.cycling74.com/reference/number/ "number") box, setting the `bindto` attribute to a valid object.
## More Ways Than One
Naming a Max object and explicitly binding a [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") to it with its `bindto` attribute is only one way to get a [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") to refer to an object in our patch. It has the advantage of requiring no connecting patchcords between the two objects, allowing them to communicate from remote parts of the patcher.
Open the subpatch `notes` by double-clicking the [patcher](https://docs.cycling74.com/reference/patcher/ "patcher") object containing it. This subpatch contains eight [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object-bound [number](https://docs.cycling74.com/reference/number/ "number") box objects that define the four pitches in our pattern generator, as well as the number of beats between each trigger of the pitch. This is the part of the patch that allows us to construct a polyrhythmic pattern off of a single [counter](https://docs.cycling74.com/reference/counter/ "counter") object (driven by the [metro](https://docs.cycling74.com/reference/metro/ "metro") object) in the main patcher. 
Click on the [message](https://docs.cycling74.com/reference/message/ "message") boxes back in the main patcher with this window open and notice that the [number](https://docs.cycling74.com/reference/number/ "number") box objects in the subpatch update correctly when you click on the different patterns. Clicking on the [message](https://docs.cycling74.com/reference/message/ "message") box updates the subpatch values, too!
In addition to binding objects to [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") through explicit naming and the bindto attribute, [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects can control other Max objects through patchcord connections. 
The notes subpatch shows two possible ways to do this:
  1. Using the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object itself to store the data (vals)
  2. Automatically _binding_ a [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object to an object using the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object’s middle outlet (mods).


## Internal Storage
If a [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object is unbound, it will store any messages sent in its left inlet and recall them from its left outlet. Messages sent to an unbound [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object from a [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub") object will echo out of the left outlet as well.
Unlock the notes subpatch and attach a [slider](https://docs.cycling74.com/reference/slider/ "slider") object to the left outlet of one of the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects named `val_a`, `val_b`, `val_c`, or `val_d`. Recall the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects’ states by clicking on the [message](https://docs.cycling74.com/reference/message/ "message") boxes in the main patch. Scroll the [number](https://docs.cycling74.com/reference/number/ "number") box attached to the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object. The [slider](https://docs.cycling74.com/reference/slider/ "slider") object should move as well.
The [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects controlling our pitches are not bound to any single object, and are maintaining the values of the [number](https://docs.cycling74.com/reference/number/ "number") box objects attached to them not by referring to the objects directly, but by receiving their values as messages. As a result, the [number](https://docs.cycling74.com/reference/number/ "number") box objects attached to these [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects can be deleted and replaced with other objects (or more than one object). Because the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object outputs its values when changed (either directly or remotely) we can easily attach multiple objects to the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object to set and display values stored in the object.
The use of the [prepend](https://docs.cycling74.com/reference/prepend/ "prepend") object with ‘set’ argument in [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") connections is to prevent the triggering of MIDI events when we recall the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object’s state. Unlike most Max objects, [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects can be connected to other objects that are directly connected to them in turn without causing a stack overflow.
## Automatic Binding
In the same subpatch, try to connect a [slider](https://docs.cycling74.com/reference/slider/ "slider") object to the middle outlet of one of the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects labeled `mod_a`, `mod_b`, `mod_c`, or `mod_d`. The Max Console should print an error message and the program should prevent you from making the connection.
The middle outlet of [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") allows for the automatic binding of the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") to a single object in the same patcher. The [number](https://docs.cycling74.com/reference/number/ "number") box objects controlling the [%](https://docs.cycling74.com/reference/%25/ "%") objects are communicating with their respective [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects just as if we had named them and bound the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects to them manually.
Look at the names for the [number](https://docs.cycling74.com/reference/number/ "number") box objects by selecting **Name…** from the **Object** menu.
The `bindto` (middle) outlet of [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects automatically gives the referring object a name if it doesn’t have one already. The name is based on the class of object attached, and multiple objects of the same class in a patch will be given incrementing notation to uniquely identify them (e.g. `number`, `number[1]`, `number[2]`, etc.).
Back in the main patch, open the `durs` subpatch of the main patch by double-clicking the [patcher](https://docs.cycling74.com/reference/patcher/ "patcher") object containing it. Observe that the two [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects in there (`min` and `max`) have been bound to two [number](https://docs.cycling74.com/reference/number/ "number") box objects through their middle outlets.
## One Hub to Rule Them All
Close the subpatchers and go back to the main tutorial patch. Look at the [message](https://docs.cycling74.com/reference/message/ "message") boxes again and notice the notation used in them to refer to [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects inside subpatchers.
Because most of our [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects are inside subpatchers, the [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub") object refers to them using a _colon-separated_ notation that takes the form
```
subpatcher:pattr_name

```

We can communicate to [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects in nested subpatchers by the same convention, e.g. a [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") named `yikes` in a patcher called `stuff` in a bpatcher called `things` would be accessed through [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub") with the name:
```
things:stuff:yikes

```

Using the [umenu](https://docs.cycling74.com/reference/umenu/ "umenu") object in the main tutorial patch, select one of the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects in the patch.
In addition to setting the state of [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects through [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub"), we can also _query_ the state of [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects, which will then tell [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub") their internal state or the value of the object to which they’re bound. We do this by sending [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub") the message `get` followed by the name of the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object we want to query, with no space in the message, e.g. `getspeed` will poll the state of the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") named `speed`.
The [number](https://docs.cycling74.com/reference/number/ "number") box to the right of the [umenu](https://docs.cycling74.com/reference/umenu/ "umenu") reflects the current value of the selected [pattr](https://docs.cycling74.com/reference/pattr/ "pattr"), output by the second outlet of [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub") as a message beginning with the name of the queried [pattr](https://docs.cycling74.com/reference/pattr/ "pattr").
Change the value of the selected [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") by changing the [number](https://docs.cycling74.com/reference/number/ "number") box next to the [umenu](https://docs.cycling74.com/reference/umenu/ "umenu"). Check to see that the value changed by looking at the [number](https://docs.cycling74.com/reference/number/ "number") box controlled by that [pattr](https://docs.cycling74.com/reference/pattr/ "pattr"). Select some other [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects and change their values, familiarizing yourself with how the system allows you to query and set the states of objects anywhere in the patch.
## Summary
The [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects provide a powerful way to manage data from multiple objects in a Max patch. The [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object can maintain its own internal information (sent and returned through its leftmost inlet and outlet), or it can bind to a Max user interface object either by naming that object and using the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object’s bindto attribute, or by using the middle outlet of the [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object to automatically name and bind to an object. Each [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object can only bind to one object at a time. The [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub") object allows you to control the state of all [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") objects within a patch, including those within subpatchers, which can be accessed through a hierarchical notation system of successive patcher names separated by colons (`:`) followed by the name of the appropriate [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object. By sending a `get` message (followed by the name of a [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") with no intervening space) you can query the state of any [pattr](https://docs.cycling74.com/reference/pattr/ "pattr") object within a patch from a [pattrhub](https://docs.cycling74.com/reference/pattrhub/ "pattrhub").

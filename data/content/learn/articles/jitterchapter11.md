# Tutorial 11: Lists and Matrices
This tutorial shows how to use Max _lists_ anf the [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") object to fill all or part of a matrix , and how to retrieve all or part of a matrix's contents as a list with [jit.spill](https://docs.cycling74.com/reference/jit.spill "jit.spill"). We will also demonstrate the use of matrix _names_ to access the contents of a matrix remotely, a concept that will be demonstrated further in _Tutorials 12, 16, and 17_.
## Matrix Names
At the left of the patch, you'll see a blue [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object. The first argument gives the matrix a specific name, `smallbox`. The remaining arguments say that the matrix will have `1` plane of `char` data, and that the matrix will have only one dimension with `12` cells. 
![This matrix has a unique name:  smallbox .](https://docs.cycling74.com/images/46b41661785410ea488447c921d10149_165.webp) This matrix has a unique name: smallbox .
In _Tutorial 2_ we explained that every matrix has a name. If we don't give a matrix a name explicitly, Jitter will choose a name arbitrarily (usually something strange like "u040000114", so that the name will be unique). The name is used to refer to the place in the computer's memory where the matrix's contents are stored. So, why give a name of our own to a matrix? That way we'll know the name, and we can easily tell other objects how to find the matrix's contents. By referring to the name of a matrix, objects can share the same data, and can access the matrix's contents remotely, without actually receiving a `jit_matrix` message.
Jitter's use of the matrix name to refer to its memory location is analogous to the way Max's [value](https://docs.cycling74.com/reference/value/ "value") object works. You can have many [value](https://docs.cycling74.com/reference/value/ "value") objects with the same name, and you can store a numeric value in any one of them and retrieve the same value from any other one of them. But there is really only one memory location for that name, so they are all sharing the same data. In a like manner, you can have more than one [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object with the same name, and they will all share the same data. Some other objects, such as [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill"), can access the contents of that matrix just by knowing its name.
## jit.fill
In _Tutorial 2_ we showed how to place a numeric value in a particular matrix location using the `setcell` message, and how to retrieve the contents of a location with the `getcell` message. Now we will show how to use the [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") object to place a whole list of values in a matrix. (Later in this chapter we'll also show how to retrieve many values at once from a matrix.) In the upper left corner of the patch there is a [message](https://docs.cycling74.com/reference/message/ "message") box containing a `list` of twelve numeric values. It's attached to a [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill")`smallbox` object. The `smallbox` argument refers to a matrix name. 
![jit.fill  puts a list of values in the named matrix](https://docs.cycling74.com/images/ede50ce081a7e7cb3e8e599625b7cbe5_314.webp) jit.fill puts a list of values in the named matrix
  * Click on the [message](https://docs.cycling74.com/reference/message/ "message") box to send the list of values to the [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill")`smallbox` object. The [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill")`smallbox` object places those values in the matrix named "smallbox". To verify that this is true, click on the [button](https://docs.cycling74.com/reference/button/ "button") above the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix")`smallbox` object to display the contents of the "smallbox" matrix. The values are printed in the Max Console by [jit.print](https://docs.cycling74.com/reference/jit.print "jit.print"), and displayed as levels of gray in a narrow [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow").


In this example, the list was exactly the right length to fill the entire matrix. That need not be the case, however. We can place a list of any length in any contiguous portion of a 1D or 2D matrix.
### The offset attribute
  * Open the `random_lists` subpatch by double-clicking it.


By default, [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") places the list of values at the very beginning of the matrix. You can direct the list to any location in the matrix, though, by setting [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") 's `offset` attribute. The `random_lists` subpatch demonstrates the use of the `offset` feature. 
![First specify the offset, then provide the list](https://docs.cycling74.com/images/a9cee31dd32c10a97978e2eac3491b70_291.webp) First specify the offset, then provide the list
This example chooses a cell index at random, uses that random number as the argument to an `offset` message to the [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill")`randbox` object, then sends a 16-element list to be stored starting at that index in the `randbox` matrix.
  * Click on the [toggle](https://docs.cycling74.com/reference/toggle/ "toggle") to start the [metro](https://docs.cycling74.com/reference/metro/ "metro"). Every half-second, the 16-element list will be written to a new location in the `randbox` matrix.

![The list has been written to four locations in the "graybox" matrix](https://docs.cycling74.com/images/3745ed35b28ce9a3aa3f3bfdbe133c1d_272.webp) The list has been written to four locations in the graybox" matrix
  * You can use the `clear` message to zero the contents of the `randbox` matrix, then watch it as the [metro](https://docs.cycling74.com/reference/metro/ "metro") writes the list into new random locations. Note that the metro is also banging the `randbox`[jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") to send its contents to the [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow") for dispaly. When you're done, turn off the [metro](https://docs.cycling74.com/reference/metro/ "metro").


## Using multiSlider
  * Open the `draw_list` subpatch.


So far we've shown how to put a predetermined list of values into a matrix. When you want to generate such a list of numbers interactively in Max and place them in a matrix in real time, you'll need to use a Max object designed for building lists. We'll look at two such objects: [multislider](https://docs.cycling74.com/reference/multislider/ "multislider"), and [zl](https://docs.cycling74.com/reference/zl/ "zl"). The [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") object displays a set of individual sliders, and it sends out the position of all of its sliders at once as a list of values. (The sliders can be as small as one pixel wide, which can make it look more like a graph than a set of individual controls.) It sends out the whole list when you click in the window to move any of the sliders, and it sends the list again when you release the mouse button. In the draw_list subpatch, we've set up a [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") to contain 256 sliders that send values from 0 to 255, so it's just right for sending a list of 256 _char_ values to the [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill")`graybox` object.
  * Use the mouse to draw in the [multislider](https://docs.cycling74.com/reference/multislider/ "multislider"), setting its 256 sliders. When you release the mouse button, the list of 256 values is sent out to the [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill")`graybox` object. Notice how the brightness of the matrix cells corresponds to the height of the sliders.


As soon as [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") receives a `list` in its inlet, it writes the values into the named matrix (at the position specified by the `offset` attribute). As soon as this is done, [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") sends a `bang` out its left outlet. You can use that `bang` to trigger another action, such as displaying the matrix.
In the first two examples we deliberately avoided using the `bang` from the left outlet of [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill"), in order to make it quite clear that [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") writes into the named matrix remotely without being physically connected to the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object. The `bang` out of [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") 's left outlet is convenient, though, for triggering the output of the matrix as soon as it has been filled.
## Using zl
  * Open the `collect_values` subpatch


In some situations you might want to use a matrix to store numeric messages that have occurred somewhere in the patch: MIDI messages, numbers from a user interface object, etc. The `setcell` and `getcell` messages to [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") are useful for that, but another way to do it is to collect the messages into a list and then place them in the matrix all at once with [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill"). The [zl](https://docs.cycling74.com/reference/zl/ "zl") object is a versatile list-processing object with many possible modes of behavior, depending on its first argument. When its first argument is `group`, it collects the messages received in its left inlet until it has amassed a certain number of them, then sends the numbers out as a single list. (The values are grouped in the order in which they were received.) So, in the `collect_values` subpatch, we have placed a [zl](https://docs.cycling74.com/reference/zl/ "zl")`group 256` object that will collect 256 values in its left inlet, and when it has received 256 of them it will send them out its left outlet as a list (and clear its own memory).
  * Move the [slider](https://docs.cycling74.com/reference/slider/ "slider") up and down to generate 256 input values for the [zl](https://docs.cycling74.com/reference/zl/ "zl") object. When [zl](https://docs.cycling74.com/reference/zl/ "zl") has received 256 numbers, it sends them as a `list` to [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill")`midibox` —which writes them into the `midibox` matrix—then `bang` s the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix")`midibox 1 char 256` object to display the matrix.

![zl  sends a 256-element list into the  midibox  matrix, then bangs  jit.matrix  to display the result](https://docs.cycling74.com/images/9803b2b29c17d4c62e28cd918814f033_290.webp) zl sends a 256-element list into the midibox matrix, then bangs jit.matrix to display the result
  * If you have a MIDI keyboard controller attached to your computer, you can use the modulation wheel of the MIDI keyboard to move the [slider](https://docs.cycling74.com/reference/slider/ "slider"). (The interaction between MIDI and Jitter is explored in detail in later tutorial chapters.)

![Values are doubled to occupy the range 0-254, making them useful as char data for the matrix](https://docs.cycling74.com/images/d8d730f910ce66e61a52c505873a1f18_200.webp) Values are doubled to occupy the range 0-254, making them useful as char data for the matrix
You can change the length of the list that [zl](https://docs.cycling74.com/reference/zl/ "zl") collects, by sending a new list length in the right inlet from the _List Length_[number](https://docs.cycling74.com/reference/number/ "number") box. And you can say _where_ in the matrix you want to put it, by sending an `offset` message to [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") from the _Location_[number](https://docs.cycling74.com/reference/number/ "number") box. By varying the list length and location, you can put any number of values into any contiguous region of the matrix.
  * Try changing the _List Length_ of [zl](https://docs.cycling74.com/reference/zl/ "zl") (to, say, `100`) and setting the _Location_ of [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") 's offset attribute (to, say `50`), then move the [slider](https://docs.cycling74.com/reference/slider/ "slider") some more to put a list of values into that particular location in the matrix.


## jit.fill with Multiple-plane Matrices
  * Open the `fill_separate_panes` subpatch


[jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") works fine with multiple-plane matrices, but it can only fill one plane at a time. The plane that [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") will access is specified in its `plane` attribute. In the `fill_separate_panes` subpatch, we've created another matrix, with four planes of _char_ data this time, named `colorbox`. We've set up three [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") s and three [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") objects, each one addressing a different color plane of the `colorbox` matrix. 
![Filling each plane independently](https://docs.cycling74.com/images/9607328d9642a808ef07788e4c776840_285.webp) Filling each plane independently
  * Drag on the three colored [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") objects to fill each of the three color planes.


This is a convenient way to generate different curves of intensity in the RGB planes of a matrix. The [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow") that's showing the matrix is actually 256 pixels wide, so each of the 64 cells of the matrix is displayed as a 4-pixel-wide band. If you turn on the `interp` attribute of the [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow"), the differences between adjacent bands will be smoothed by interpolation.
  * Click on the [toggle](https://docs.cycling74.com/reference/toggle/ "toggle") above the `interp $1`[message](https://docs.cycling74.com/reference/message/ "message") box to send the message `interp 1` to [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow"). (Note that this also sends a `bang` to [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") to re-display its contents.

![The same as the previous example, but with interpolation turned on in  jit.pwindow](https://docs.cycling74.com/images/ecde97221f60351ea11795fa080174e0_278.webp) The same as the previous example, but with interpolation turned on in jit.pwindow
### jit.fill with 2D Matrices
So far, all of our examples have involved one-dimensional matrices. What happens when you use a list (which is a one-dimensional array) to fill a two-dimensional matrix via [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") ? The [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") object will use the list to fill as far as it can in the first dimension (i.e. it will go as far as it can the specified row), then it will wrap around to the next row and continue at the beginning of that row. We've made it possible for you to see this wrapping effect in action.
  * Click on the button labeled _2D_. This will change the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix")`colorbox` object to contain a two-dimensional 8x8 matrix, and will also resize the [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow") to a more appropriate shape. Whenever you change the dimensions of a matrix, it loses its contents, so you will need to click in the three [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") s again to fill the matrix anew. You are still sending a 64-element `list` to each of the [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") objects, and they fill each of the eight rows of the matrix with eight elements.


Important: Although we don't demonstrate the use of the `offset` attribute with a 2D matrix in this patch, it's worth mentioning that when the `name` attribute of [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") names a 2D matrix, the `offset` attribute requires _two_ arguments: one for the _x_ offset and one for the _y_ offset.
[jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") _only works for 1D and 2D matrices._
![The same example, with each list wrapped around in an 8x8 matrix \(shown uninterpolated\)](https://docs.cycling74.com/images/9d566d8eb397a44110bef0a25a0c7bae_278.webp) The same example, with each list wrapped around in an 8x8 matrix (shown uninterpolated) ![The same example, displayed with interpolation](https://docs.cycling74.com/images/e8a9edaa3962bd05a92fb95c89d6c9ba_274.webp) The same example, displayed with interpolation
## jit.spill
The complementary object to [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") is [jit.spill](https://docs.cycling74.com/reference/jit.spill "jit.spill"). It takes a `jit_matrix` message in its inlet, and sends the matrix values out its left outlet as a Max `list`. You may have noticed that while you were using the red [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") the [jit.spill](https://docs.cycling74.com/reference/jit.spill "jit.spill") object below was sending the values of plane 1 (red) out its left outlet and setting the contents of a [message](https://docs.cycling74.com/reference/message/ "message") box. 
![The contents of plane 1 of the "colorbox" matrix, displayed as a Max list](https://docs.cycling74.com/images/8cdb2dfcf316db7e3ebd78be68c3debe_308.webp) The contents of plane 1 of the colorbox" matrix, displayed as a Max list
Although not demonstrated in the patch, [jit.spill](https://docs.cycling74.com/reference/jit.spill "jit.spill") also has `listlength` and `offset` attributes that let you specify exactly _how many_ values you want to list, and from exactly _what location_ in the matrix.
If you need to have the values as an immediate series of individual number messages rather than as a single list message, you can send the list to the Max [iter](https://docs.cycling74.com/reference/iter/ "iter") object. 
![Get a few values from the matrix and make them into separate messages](https://docs.cycling74.com/images/6b3f20f98296bdd4fe9b743eb726f64c_282.webp) Get a few values from the matrix and make them into separate messages
## jit.iter
  * Open the `individual_values` subpatch.


For times when you need to retrieve _every_ value in a matrix, there is an object called [jit.iter](https://docs.cycling74.com/reference/jit.iter "jit.iter"). When it receives a `jit_matrix` message in its inlet, it sends out an as-fast-as-possible sequence of messages: the cell index (out its middle outlet) followed by the value(s) in that cell (out its left outlet) for every cell of the matrix in order. For a large matrix, this can be an awful lot of Max messages to try to send out in a single tick of Max's scheduler, so when it's done reporting all of the values in a matrix [jit.iter](https://docs.cycling74.com/reference/jit.iter "jit.iter") sends a `done` message out its right outlet. In the `individual_values` subpatch there is a [jit.iter](https://docs.cycling74.com/reference/jit.iter "jit.iter") object which receives the matrix information from the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix")`readbox 1 char 256` object. We use a [swap](https://docs.cycling74.com/reference/swap/ "swap") object to switch the order of the cell index (coming out the middle outlet of [jit.iter](https://docs.cycling74.com/reference/jit.iter "jit.iter")) and the cell value (coming out the left outlet of [jit.iter](https://docs.cycling74.com/reference/jit.iter "jit.iter")). We then use the value of that cell as the _y_ -value we want to store in a [table](https://docs.cycling74.com/reference/table/ "table") object, and we use the cell index as the _x_ -axis index for the [table](https://docs.cycling74.com/reference/table/ "table") .
  * Click on the [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") object to send its contents to [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") (which will in turn `bang` the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object and communicate its contents to [jit.iter](https://docs.cycling74.com/reference/jit.iter "jit.iter"). Then double-click the [table](https://docs.cycling74.com/reference/table/ "table") object to open its graphic window and see that it contains the same values as the `readbox` matrix.


Note that this technique of using [jit.iter](https://docs.cycling74.com/reference/jit.iter "jit.iter") to fill a [table](https://docs.cycling74.com/reference/table/ "table") works well with a modest-sized one-dimensional one-plane matrix because a [table](https://docs.cycling74.com/reference/table/ "table") is a one-dimensional array. However, the matrix of a [jit.movie](https://docs.cycling74.com/reference/jit.movie "jit.movie") object, for example, has two dimensions and four planes, so in that case the output of [jit.iter](https://docs.cycling74.com/reference/jit.iter "jit.iter") 's middle (cell index) outlet would be a two-element list, and the output of the left (value) outlet would be a four-element list. 
![What are ya gonna do with all those numbers?](https://docs.cycling74.com/images/a4f1076851d4618f8d951d1025016d77_483.webp) What are ya gonna do with all those numbers?
Still, for one-dimensional matrices, or small 2D matrices, or even for searching for a particular value or pattern in a larger matrix, [jit.iter](https://docs.cycling74.com/reference/jit.iter "jit.iter") is useful for scanning an entire matrix.
## Summary
For placing individual values in a matrix, or retrieving individual values from a matrix, you can use the `setcell` and `getcell` messages to [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") (as was demonstrated in _[Jitter Tutorial 2](https://docs.cycling74.com/learn/articles/jitterchapter02/)_). For placing a whole list of values in a matrix, or retrieving a list of values from a matrix, use the objects [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") and [jit.spill](https://docs.cycling74.com/reference/jit.spill "jit.spill"). These objects work well for addressing any plane of a 1D or 2D matrix, and they allow you to address any list length at any starting cell location in the matrix. The [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") and [zl](https://docs.cycling74.com/reference/zl/ "zl") objects are useful for building Max list messages in real time. With [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") you can draw a list by dragging on the sliders with the mouse. With [zl](https://docs.cycling74.com/reference/zl/ "zl")`group` you can collect many individual numeric values into a single list, then send them all to [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") at one time. You specify the starting cell location in the matrix by setting the `offset` attribute of [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") (or [jit.spill](https://docs.cycling74.com/reference/jit.spill "jit.spill")). The [jit.fill](https://docs.cycling74.com/reference/jit.fill "jit.fill") object requires that you set its `name` attribute (either by sending it a `name [name]` message or by typing in a `[name]` argument), specifying the name of the matrix it will fill. It accesses the matrix using this name, and sends a `bang` out its outlet whenever it has written a list into the matrix. You can use that `bang` to trigger other actions. In _Tutorials 12_ , _16_ , and _17_ we show some practical uses of accessing a matrix by its name.
To output every value in an entire matrix, you can send the matrix to [jit.iter](https://docs.cycling74.com/reference/jit.iter "jit.iter").

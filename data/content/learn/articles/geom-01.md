# Getting Started with Jitter Geometry
The `jit.geom` family of objects, like [jit.geom.shape](https://docs.cycling74.com/reference/jit.geom.shape "jit.geom.shape"), are a specialized group of Jitter objects designed to work with **Half-edge Geometry Structures**. We'll talk about some of the details later, but for now the most important thing to keep in mind is that this way of representing geometries makes certain kinds of geometry manipulations much easier and more efficient:
  * _Generating shapes_ - Use [jit.geom.shape](https://docs.cycling74.com/reference/jit.geom.shape "jit.geom.shape") to create simple geometries with an arbitrary number of subdivisions.
  * _Vertex adjustment_ - The [jit.geom.remesh](https://docs.cycling74.com/reference/jit.geom.remesh "jit.geom.remesh") object lets you rearrange the vertices of a geometry, making them more evenly distributed without changing the overall shape. You can add and remove vertices with [jit.geom.subdivide](https://docs.cycling74.com/reference/jit.geom.subdivide "jit.geom.subdivide") and [jit.geom.decimate](https://docs.cycling74.com/reference/jit.geom.decimate "jit.geom.decimate").
  * _Transformations_ - Smooth out a geometry with [jit.geom.smooth](https://docs.cycling74.com/reference/jit.geom.smooth "jit.geom.smooth"), add roughness or procedural displacement with [jit.geom.dimples](https://docs.cycling74.com/reference/jit.geom.dimples "jit.geom.dimples") and [jit.geom.displace](https://docs.cycling74.com/reference/jit.geom.displace "jit.geom.displace"), or perform more radical transformations with [jit.geom.twist](https://docs.cycling74.com/reference/jit.geom.twist "jit.geom.twist"), [jit.geom.waves](https://docs.cycling74.com/reference/jit.geom.waves "jit.geom.waves"), and [jit.geom.xform](https://docs.cycling74.com/reference/jit.geom.xform "jit.geom.xform").
  * _Property generation_ - Create dynamic, adjustable shapes with lifelike surface properties, using [jit.geom.texgen](https://docs.cycling74.com/reference/jit.geom.texgen "jit.geom.texgen") and [jit.geom.normgen](https://docs.cycling74.com/reference/jit.geom.normgen "jit.geom.normgen") to generate texture coordinates and surface normals.


## Making a Shape
Open the patch `geom-01.maxpat`.
![](https://docs.cycling74.com/images/db193c40ac5cc6a9a103525833495b04_1024.webp)
When you first look at this patch, you'll notice something brand new: a striped, red patch cable connecting from every `jit.geom` object. This cable carries half-edge geometry. As you can see, the [jit.geom.shape](https://docs.cycling74.com/reference/jit.geom.shape "jit.geom.shape") object creates simple 3D forms, very similar to the [jit.gl.gridshape](https://docs.cycling74.com/reference/jit.gl.gridshape "jit.gl.gridshape") object. However, if you take a close look at the default shape, the _icosphere_ , you'll see that it looks very different from the "sphere" shape generated by [jit.gl.gridshape](https://docs.cycling74.com/reference/jit.gl.gridshape "jit.gl.gridshape").
![](https://docs.cycling74.com/images/f4413d1dc388d0f1b32e14567d4b6a67_1024.webp) On the left, a sphere generated by jit.gl.gridshape. On the right, a sphere generated by jit.geom.shape.
In fact, the name of this geometry—icosphere—describes the equal distribution of points around the center of the sphere. Now, try changing the value of the `@divisions` attribute on [jit.geom.sphere](https://docs.cycling74.com/reference/jit.geom.sphere "jit.geom.sphere"). Notice how the number of faces changes.
![](https://docs.cycling74.com/images/9498e25d3cbae4aadd578b70bd4866be_1024.webp) An icosphere from jit.geom.sphere with divisions 2, 3, and 4
If you look carefully, you can see that every time you increase the number of divisions, you're dividing each face into three new faces. This is a big clue as to how the half-edge geometry is working under the hood. The real power that the half-edge representation gives us is that each vertex "knows" something about which vertices are adjacent to it. So, it's relatively easy to add more vertices relative to existing ones.
## Making Normals
Now, try changing the `@type` of [jit.geom.norgen](https://docs.cycling74.com/reference/jit.geom.norgen "jit.geom.norgen") to something other than `face`. You should see the shape change to something nice and smooth.
Unlike [jit.gl.gridshape](https://docs.cycling74.com/reference/jit.gl.gridshape "jit.gl.gridshape") the [jit.geom.shape](https://docs.cycling74.com/reference/jit.geom.shape "jit.geom.shape") object doesn't generate surface normals. Without these normals, the graphics engine doesn't know the orientation of the object's surface. An object with no surface normals always looks completely flat, no matter how it's lit.
![](https://docs.cycling74.com/images/28c394f915776817d386d4dd12a03cc8_913.webp) If you bypass the jit.geom.normgen object, you'll end up with a completely flat looking object.
The reason [jit.geom.shape](https://docs.cycling74.com/reference/jit.geom.shape "jit.geom.shape") object doesn't make surface normals is so that you can do this step on demand after you've transformed the geometry of your shape. If you've ever tried to distort the surface of a geometry from [jit.gl.gridshape](https://docs.cycling74.com/reference/jit.gl.gridshape "jit.gl.gridshape"), maybe you've noticed that it looks weirdly flat.
![](https://docs.cycling74.com/images/bdc10495de063b018e392950b043fd1c_852.webp) On the left, a distorted sphere from jit.gl.gridshape. On the right, the same distorted sphere, but with normals recomputed to show the true contortion of the surface.
This is because moving the vertices around doesn't change the surface normals, so it doesn't change the orientation of the faces between the vertices. Later versions of Max added the `@auto_normals` attribute to [jit.gl.mesh](https://docs.cycling74.com/reference/jit.gl.mesh "jit.gl.mesh"), which gets around this somewhat. However, [jit.geom.normgen](https://docs.cycling74.com/reference/jit.geom.normgen "jit.geom.normgen") is an even more flexible approach.
Finally, you'll see that we're connecting the output of [jit.geom.normgen](https://docs.cycling74.com/reference/jit.geom.normgen "jit.geom.normgen") into an object called [jit.geom.tomatrix](https://docs.cycling74.com/reference/jit.geom.tomatrix "jit.geom.tomatrix"). This converts from geometry back into a matrix. By default, this object will also compute surface normals, so we've added `@auto_normals 0` to make sure that only [jit.geom.normgen](https://docs.cycling74.com/reference/jit.geom.normgen "jit.geom.normgen") computes these normals.
There is also an object [jit.geom.tomesh](https://docs.cycling74.com/reference/jit.geom.tomesh "jit.geom.tomesh"), which is designed to work specifically with [jit.gl.mesh](https://docs.cycling74.com/reference/jit.gl.mesh "jit.gl.mesh"). We could have used that object here as well.
## Asynchrony
Now, try setting the number of divisions to something really high, like 8. If you don't see any change, try setting `@divisions` to 9 or 10. Eventually, you should see Max stall a bit (it's a lot of computation), and you'll see the appearance of the [jit.geom.normgen](https://docs.cycling74.com/reference/jit.geom.normgen "jit.geom.normgen") and [jit.geom.tomatrix](https://docs.cycling74.com/reference/jit.geom.tomatrix "jit.geom.tomatrix") change to look something like this:
![](https://docs.cycling74.com/images/0c5ae0a74a584384e9fd6cb04b0865df_261.webp) When a Jitter geometry object is actively processing, it shows zebra stripes.
By default, the Jitter geometry objects are _asynchronous_. That means that when you change their attributes or send them a new geometry, the result doesn't come out of the object's outlet right away. This is done in order to avoid blocking the rest of the Max application during an expensive computation.
## Wrapping Up
In this quick intro to Jitter Geometry, we looked at the [jit.geom.shape](https://docs.cycling74.com/reference/jit.geom.shape "jit.geom.shape") object for creating simple geometries, and the [jit.geom.normgen](https://docs.cycling74.com/reference/jit.geom.normgen "jit.geom.normgen") object for generating surface normals. If you want to have a little bit of fun (just a little, not too much), click the toggle in the top-right of the patch.

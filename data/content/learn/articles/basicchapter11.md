# Tutorial 11: Procedural Drawing
## Introduction
In this tutorial, we will be using several new objects to perform _procedural_ drawing with the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object. The [counter](https://docs.cycling74.com/reference/counter/ "counter") object will provide enumerated step processing, the [line](https://docs.cycling74.com/reference/line/ "line") object will allow us to create smoothed output, and the [scale](https://docs.cycling74.com/reference/scale/ "scale") object will allow us to change the range of output. Finally, we will introduce a few mathematical objects that will help us create some common shapes that require simple trigonometry.
We often use programmatic and procedural constructs to perform tasks in our programs; these can present new opportunities for graphic display, but can also be used any time we need to count through a set of numbers, create a numerical trajectory, or scale values. Whether used for audio visualization, controller feedback or just an interesting bit of art, procedural code can serve as both a useful tool and an inspiration.
## Using [counter](https://docs.cycling74.com/reference/counter/ "counter") to draw
Take a look at the tutorial patcher. This patch has a few areas that help us understand some new objects, and another large drawing patch. At the top-left is a small patch that demonstrates the [counter](https://docs.cycling74.com/reference/counter/ "counter") object. When we click on the left [button](https://docs.cycling74.com/reference/button/ "button"), the object produces numeric output that increments by `1` for each `bang` message it receives. When the output reaches `9`, the next `bang` will reset the output to `0`. The arguments we've provided here to the [counter](https://docs.cycling74.com/reference/counter/ "counter") provide the _minimum_ and _maximum_ numbers for the output. When the object hits its maximum, it will loop back again to the minimum number. This allows us to use [counter](https://docs.cycling74.com/reference/counter/ "counter") to create _loops_ of values.
The [counter](https://docs.cycling74.com/reference/counter/ "counter") object is somewhat unusual in that it can accept a variable number of arguments:
  * If you have _one_ argument, it sets the _maximum_ value of the [counter](https://docs.cycling74.com/reference/counter/ "counter").
  * If you have _two_ arguments, they set the _minimum_ and _maximum_ values of the [counter](https://docs.cycling74.com/reference/counter/ "counter").
  * If you have _three_ arguments, they set the _direction_ , _minimum_ and _maximum_ values of the [counter](https://docs.cycling74.com/reference/counter/ "counter").


Our test patch for [counter](https://docs.cycling74.com/reference/counter/ "counter") includes an additional [button](https://docs.cycling74.com/reference/button/ "button") (colored red) and two [number](https://docs.cycling74.com/reference/number/ "number") boxes to set values of the object. This is a great opportunity to use the _assistance_ on inlets to find out what they do. If we _unlock_ the patch and hover over the third inlet (which has both a [button](https://docs.cycling74.com/reference/button/ "button") and [number](https://docs.cycling74.com/reference/number/ "number") box connected), the assistance says “Resets Counter to Number on Next Clock”. This lets us change the current value of the [counter](https://docs.cycling74.com/reference/counter/ "counter") while it is running.
If we change the [number](https://docs.cycling74.com/reference/number/ "number") box to `5` then hit the first [button](https://docs.cycling74.com/reference/button/ "button"), we see that the output is the number `5` – regardless of what the previous value was. This is how we set the state of the [counter](https://docs.cycling74.com/reference/counter/ "counter") on the fly. Clicking on the second (red) [button](https://docs.cycling74.com/reference/button/ "button") (which sends the `bang` message) will reset the value to the minimum: `0` in this case.
The [number](https://docs.cycling74.com/reference/number/ "number") box on the right allows us to change the maximum value on the fly. This would be useful for drawing situations where you might need to change the size of the drawing area, or when you are sequencing an effect and need to change the number of steps. When we change this value and repeatedly hit the [button](https://docs.cycling74.com/reference/button/ "button"), we see that the new maximum value is honored.
The [patcher](https://docs.cycling74.com/reference/patcher/ "patcher") object labeled **example 1** is where we use the [counter](https://docs.cycling74.com/reference/counter/ "counter") object to procedurally draw in the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object. When we start the [metro](https://docs.cycling74.com/reference/metro/ "metro") (using the connected [toggle](https://docs.cycling74.com/reference/toggle/ "toggle") object), we see that the patch begins drawing small circles in the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd"), with the color gradually changing as it progresses. When the drawing reaches the bottom of the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd"), it restarts drawing at the top.
  * Double click the `example 1`[patcher](https://docs.cycling74.com/reference/patcher/ "patcher") object to open it.


Four different [counter](https://docs.cycling74.com/reference/counter/ "counter") objects are used in this patch; one to set the drawing location and size, and three others to change the color. Understanding the leftmost [counter](https://docs.cycling74.com/reference/counter/ "counter") is the most important: it counts from `0` to `767`, giving us `768` steps total. The drawing X/Y location is calculated with the [%](https://docs.cycling74.com/reference/%25/ "%") (modulo) and [/](https://docs.cycling74.com/reference/%2F/ "/") (division) objects, breaking up our lcd object into a `32` x `24` grid. If we look at the output of the [counter](https://docs.cycling74.com/reference/counter/ "counter") and the [%](https://docs.cycling74.com/reference/%25/ "%") and [/](https://docs.cycling74.com/reference/%2F/ "/") objects, we can see that the system works by creating two loops. The output of the [%](https://docs.cycling74.com/reference/%25/ "%") object loops from 0 to 31 repeatedly, once for each row. At the same time, the output of the [/](https://docs.cycling74.com/reference/%2F/ "/") object loops once from 0 to 23, incrementing by 1 at the end of each row. The values are multiplied by `10` (to get the pixel location for the top-left corner of the shape), then have `10` added (to get the pixel location for the bottom-right). This sets up a lcd-filling grid of circles for our program to draw.
The three other [counter](https://docs.cycling74.com/reference/counter/ "counter") objects cycle through three different number ranges to give us an ever-changing color palette. These [counter](https://docs.cycling74.com/reference/counter/ "counter") objects use the three-argument initialization, where the initial `2` forces the counter to move upward to the maximum, then downward to the minimum. This is what causes the drawing to slowly change colors as it draws. Clicking the [button](https://docs.cycling74.com/reference/button/ "button") labeled "reset" will restart the simulation from the beginning of the loop.
## Using [scale](https://docs.cycling74.com/reference/scale/ "scale") to draw
If we return to the left of the patcher, the second small example shows the use of the [scale](https://docs.cycling74.com/reference/scale/ "scale") object. This object allows you to set a range of input values and a range of output values; the object will then correctly _scale_ the values so that they are mapped into the new number range. In our example, input values between `0` and `100` are mapped to the range of `-1.0` to `1.0` – this is determined by the arguments provided to the object. If you change the input [number](https://docs.cycling74.com/reference/number/ "number") box, you will see that a value of `0` yields an output of `-1.0`, a value of `50` will give us a value of `0.0`, and a value of `100` will give us a result of `1.0`. These numbers are mapped in a linear fashion across the range we provide.
If you choose to exceed the input range, you will find that the output continues to use the calculated range effect, thereby allowing you to exceed the expected range without failing. Hence, an input value of `150` will translate into an output of `2.0`, while a value of `-100` will give you a value of `-3`.
The [patcher](https://docs.cycling74.com/reference/patcher/ "patcher") object labeled **example 2** uses [scale](https://docs.cycling74.com/reference/scale/ "scale") to draw a shape based on sine wave calculations. A [counter](https://docs.cycling74.com/reference/counter/ "counter") object produces output ranging from `0` to the maximum value (set using the two [number](https://docs.cycling74.com/reference/number/ "number") boxes to the right of the [metro](https://docs.cycling74.com/reference/metro/ "metro") object). This is scaled from `0.0` to `6.283185` (2*pi), then sent to a [sin](https://docs.cycling74.com/reference/sin/ "sin") object, which calculates the _sine_ of the input value. This produces a sine wave that varies from `-1.0` to `1.0` in range. This value is sent to another [scale](https://docs.cycling74.com/reference/scale/ "scale") object which maps this range to the integer range `0` to `319` – the size range of the `lcd` object. This is used to provide the X locations of the line. A similar set of functions are used to set the Y location. These numbers are then inserted into a list using [pack](https://docs.cycling74.com/reference/pack/ "pack"), attached to a `lineto` message (using [prepend](https://docs.cycling74.com/reference/prepend/ "prepend")) and then sent to the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd").
Clear the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") using the [message](https://docs.cycling74.com/reference/message/ "message") box containing the `clear` message. Turn on the [metro](https://docs.cycling74.com/reference/metro/ "metro") using the [toggle](https://docs.cycling74.com/reference/toggle/ "toggle"), and watch the result. The result is a sine-based drawing over the entire [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") face. You can set the maximum values of the procedure by altering the [number](https://docs.cycling74.com/reference/number/ "number") boxes that are attached to the [counter](https://docs.cycling74.com/reference/counter/ "counter") objects. Note that the [number](https://docs.cycling74.com/reference/number/ "number") boxes change not only the parameters of the [counter](https://docs.cycling74.com/reference/counter/ "counter") objects, but also the maximum input range expected by the [scale](https://docs.cycling74.com/reference/scale/ "scale") objects immediately below (the third inlet for the [scale](https://docs.cycling74.com/reference/scale/ "scale") object determines the maximum input range expected).
The two [counter](https://docs.cycling74.com/reference/counter/ "counter") objects, when set to different maximum points, create different interlocking sine waves that draw across the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd"). These curves are called _lissajous_ patterns and simulate what happens when out-of-phase oscillators are fed into the X and Y inputs of an oscilloscope. This is a great example of using simple math functions to create complex drawings.
## Using [line](https://docs.cycling74.com/reference/line/ "line") to draw
Going back to the top-left of the patch, the third example gives us a chance to see the [line](https://docs.cycling74.com/reference/line/ "line") object in action. The [line](https://docs.cycling74.com/reference/line/ "line") object takes a pair of incoming values (configured as a value/time pairing) and slowly moves from one value to the next. If a single value is received, it jumps immediately to that value. However, when a second value is provided, it is treated as the number of milliseconds used to move to that new value.
Clicking on the first [message](https://docs.cycling74.com/reference/message/ "message") box (labeled `100 1000`) will move the [line](https://docs.cycling74.com/reference/line/ "line") from the starting value of `0` to the target value (`100`) over `1000` milliseconds. Clicking on it again will show no change, because the current value (which remains at `100`) is the same as the target value (it has nowhere to go). The line object is “state aware”, meaning that it understands its current value, and will adjust its action based on the state of that value.
Clicking on the second [message](https://docs.cycling74.com/reference/message/ "message") box (`0 5000`) will move the output of the [line](https://docs.cycling74.com/reference/line/ "line") back to `0` over `5000` milliseconds (5 seconds). Clicking on the first box will move us back to `100`.
The third [message](https://docs.cycling74.com/reference/message/ "message") box is a little more interesting. It uses a special function of the [message](https://docs.cycling74.com/reference/message/ "message") box to create multiple messages; when a _comma_ separates values, they are treated as separate messages, and will function as if two messages were sent down the same patch cord immediately after one another. In this case, the value `20` is sent as the first message. Since there is no time pairing, the current value out of the [line](https://docs.cycling74.com/reference/line/ "line") immediately jumps to `20`. Immediately afterward, the `50 2500` pair is sent, causing the output to slide from `20` to `50` over 2.5 seconds. We can also use the [number](https://docs.cycling74.com/reference/number/ "number") box to immediately jump the [line](https://docs.cycling74.com/reference/line/ "line") to a new value; since no timing value is provided, it too will cause the current state to jump to the entered value.
The [patcher](https://docs.cycling74.com/reference/patcher/ "patcher") labeled **example 3** is the most complex procedure we’ve yet seen. It depends on the `idle` mechanism of the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object to do some procedural drawing. When the `idle` message is turned on (with the `idle 1` message), the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object outputs the current mouse location relative to the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object's canvas when you move your mouse over it. These X/Y coordinates are sent as a list out the second outlet of the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd").
The light blue patchcord out of the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") connects our mouse coordinates to an [unpack](https://docs.cycling74.com/reference/unpack/ "unpack") object at the top of patch 3. These values are sent into our drawing code, which creates a set of values used to draw a pair of round shapes that follow the cursor. The [line](https://docs.cycling74.com/reference/line/ "line") object is used to slow the changes in the shapes, and causes them to slowly "zero in" on the current cursor location. Turn on the `idle` message with the [toggle](https://docs.cycling74.com/reference/toggle/ "toggle") box, then mouse around the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object to see how it reacts.
There are two very important things in this procedure. First, the use of the [line](https://docs.cycling74.com/reference/line/ "line") object to slew the output values over a one second (`1000` ms) timeframe. This gives the results a more organic feel by causing them to _interpolate_ over time. Secondly, we use the [cartopol](https://docs.cycling74.com/reference/cartopol/ "cartopol") (**car** tesian **to****pol** ar) object to change the X/Y ("Cartesian") position of the cursor into a Distance/Angle ("Polar") pair of coordinates, useful for drawing contents in a circular domain. Once the polar coordinates are calculated, they are scaled to match the size of the circular drawing area, then used as part of a complex, multi-message [message](https://docs.cycling74.com/reference/message/ "message") box to create the two “eyes” found in the middle of the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object.
The [message](https://docs.cycling74.com/reference/message/ "message") box at the bottom of the code sends five drawing commands in sequence to the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd"). The beginning `clear` removes the last drawing to provide continuous animation. The next two draw two background circles using the `paintoval` command at fixed positions (`100 100 140 140` and `180 100 220 240`). The last three arguments to `paintoval` set the color (black: `0 0 0`). The final two messages use the values from the [pack](https://docs.cycling74.com/reference/pack/ "pack") object to draw green "pupils" on the eyes. The four values provide the starting and ending angle for the pupils using the `paintarc` message.
Understanding all of the functionality of this procedure may be difficult, but it is worth it – this is another example of using some mathematical programming to create a complex and life-like end result. Simple realtime graphics are made out of building blocks of procedural code just like this; taking a set of input values and scaling them to your needs is critical for many applications in Max.
## Summary
We’ve seen some fairly complex programming that provides controlled drawing functionality within an [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object by creating loops ([counter](https://docs.cycling74.com/reference/counter/ "counter")), scaling input values to output values ([scale](https://docs.cycling74.com/reference/scale/ "scale")), and interpolating numbers over time ([line](https://docs.cycling74.com/reference/line/ "line")). We’ve also worked with a few objects that compute trigonometry. By using these new objects in combination, we can assert a lot of procedural control over what we want to accomplish in our programs.

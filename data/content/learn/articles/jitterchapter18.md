# Tutorial 18: Iterative Processes and Matrix Re-Sampling
This tutorial demonstrates a more complicated example of when to use named [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") objects, as well as how to use [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") objects to upsample and downsample an image. The upper left-hand corner of the patch contains a [jit.movie](https://docs.cycling74.com/reference/jit.movie "jit.movie") object that has a still image (the file _fuzz_circle.jpg_) loaded into it when the patch opens.
![Read the image](https://docs.cycling74.com/images/d9b306bfd9601590f10378f549ce3709_191.webp) Read the image
  * Start the [metro](https://docs.cycling74.com/reference/metro/ "metro") object by clicking the [toggle](https://docs.cycling74.com/reference/toggle/ "toggle") box above it. You should see an image appear in the [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow") in the lower right of the tutorial patch:

![Our little comet](https://docs.cycling74.com/images/8263cb0e0dca15360cd3d7932e00669b_321.webp) Our little comet
The _fuzz_circle.jpg_ file contains an image of a white circle with a black background, which is being scaled in size to appear as a small circle inside of our final matrix.
![The real fuzz circle](https://docs.cycling74.com/images/e11f34d6dfc760015ea7eba57eddd7a6_173.webp) The real fuzz circle
## Getting Drunk
The top part of the patch writes the image from the [jit.movie](https://docs.cycling74.com/reference/jit.movie "jit.movie") into the first [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object in the chain. A `bang` generated by the [bangbang](https://docs.cycling74.com/reference/bangbang/ "bangbang") object changes the `dstdimstart` and `dstdimend` attributes of the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object with each frame, randomly varying the coordinates using Max [drunk](https://docs.cycling74.com/reference/drunk/ "drunk") objects. Note that our first [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object has its `usedstdim` attribute set to `1`, so that it will scale the input matrix:
![The drunk part of the patch](https://docs.cycling74.com/images/368355f41c889608f921065721bbca5c_369.webp) The drunk part of the patch
This first [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix"), therefore, simply serves to scale the circle image to fit in a small (80 by 60) region of our output matrix. Note that the [message](https://docs.cycling74.com/reference/message/ "message") box that formats the coordinates for the scaled image also clears the matrix with every frame (with a `clear` message), so that there are no artifacts from a previously written image. The Max [drunk](https://docs.cycling74.com/reference/drunk/ "drunk") objects vary the placing of the circle, causing it to jitter around (no pun intended).
  * Click somewhere in the [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow") in the lower right corner of the patch. The circle will jump to the position you clicked, and begin to move from there.


The result of a mouse click in the [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow") is sent to the [receive](https://docs.cycling74.com/reference/receive/ "receive") object with the name `winclick`. This message is then stripped of its selector (`mouse`) and the first two elements (the x and y position of the mouse click) are extracted by the [unpack](https://docs.cycling74.com/reference/unpack/ "unpack") object. These coordinates are then used to set the new origin for the [drunk](https://docs.cycling74.com/reference/drunk/ "drunk") objects.
## The Feedback Network
Once our circle image has been scaled and placed appropriately by the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object, our patch enters a feedback chain that centers around a pair of [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") objects sharing a matrix named `blurry` :
![The feedback loop in our patch](https://docs.cycling74.com/images/d9fd65be7b8440e2a822eedab1dc3ecd_269.webp) The feedback loop in our patch
This section of the patch contains four [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") objects (not including the one at the top which scales down the circle image). Two of the objects share a `name` (`blurry`) and are used simply to store and retreive previous matrices generated by the rest of the patch. The topmost [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object sends its matrix to the rightmost inlet of the first [jit.op](https://docs.cycling74.com/reference/jit.op "jit.op") object in the patch. In addition, it sends a `bang` to the first named [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object using a [bangbang](https://docs.cycling74.com/reference/bangbang/ "bangbang") object, causing it to output its stored matrix (called `blurry`). This matrix eventually ends up in the left inlet of the [jit.op](https://docs.cycling74.com/reference/jit.op "jit.op"), where it is then displayed (by the [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow")) and multiplied by a scalar (the second [jit.op](https://docs.cycling74.com/reference/jit.op "jit.op") object). It eventually overwrites the previous `blurry` matrix (by going into the bottom named [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object). Without worrying about what the intermediate Jitter objects do, you can see that the `blurry` matrix will hold some version of the previous 'frame' of our circle image:
![A scaled-down and illustrated map of our patch](https://docs.cycling74.com/images/b0726cad6baebe6ba9e2aca4a1e6c584_347.webp) A scaled-down and illustrated map of our patch
The new and old images are combined by the first [jit.op](https://docs.cycling74.com/reference/jit.op "jit.op") object using the `max` operator. The `max` operator compares each cell in the two matrices and retains the cell with the highest value. The second [jit.op](https://docs.cycling74.com/reference/jit.op "jit.op") object (with the `*` operator) serves to darken our image by multiplying it by a scalar (set by the [number](https://docs.cycling74.com/reference/number/ "number") box on the right of the patch that is sent to the [receive](https://docs.cycling74.com/reference/receive/ "receive") object named `fb`):
![The feedback amount sets how much the image is darkened before being stored in the  blurry  matrix.](https://docs.cycling74.com/images/9189bebdd7ac3e996fa7a08572e7d71d_135.webp) The feedback amount sets how much the image is darkened before being stored in the blurry matrix.
  * Change the feedback amount of the patch by playing with the [number](https://docs.cycling74.com/reference/number/ "number") box labeled _Feedback_ in the blue region of the patch. Notice how the trails after the circle increase or decrease when you move the circle by clicking in the [jit.pwindow](https://docs.cycling74.com/reference/jit.pwindow "jit.pwindow"), depending on how the feedback amount is set.


## Downsampling and Upsampling
The final step in our image processing algorithm concerns the part of the patch in between the first named [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix"), which sends out the matrix saved there during the previous frame by the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") at the bottom, and the first [jit.op](https://docs.cycling74.com/reference/jit.op "jit.op") object, which composites the previous matrix with the new one:
![Using jit.matrix objects for resampling of an image](https://docs.cycling74.com/images/48b94df21d76857d1092fd745efcdbc5_230.webp) Using jit.matrix objects for resampling of an image
The two [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") objects colored green in the tutorial patch are used to _resample_ the `blurry` image matrix coming out of the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object above them. The first of the two [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") objects has its `dim` attibute set to `4` x `4` cells. This size can be changed by setting the attribute with the [number](https://docs.cycling74.com/reference/number/ "number") box in the blue region with the caption _Pixelation_. This number gets sent to the [receive](https://docs.cycling74.com/reference/receive/ "receive") object named `dim` above the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object.
![Change the pixelation of the trails](https://docs.cycling74.com/images/db74683b767341c8951e0fbbff4b9a55_118.webp) Change the pixelation of the trails
  * Change the [number](https://docs.cycling74.com/reference/number/ "number") box labeled _Pixelation_ in the blue region of the tutorial patch. Notice how the circle trails change.


By downsampling the image matrix, the [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object copies the `320` x `240` matrix from its input into a much smaller matrix, jettisoning excess data. The result is a pixelation of the image that you can control with the `dim` of the matrix.
The second [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") object upsamples the matrix back to a `320` x `240` matrix size. This is so that when subsequent Jitter objects process the matrix, they will have a full resolution image to work with and will output a full resolution matrix.
The [jit.streak](https://docs.cycling74.com/reference/jit.streak "jit.streak") object adds a nice effect to the pixelated trails by randomly 'streaking' cells into their neighbors. The `prob` attribute of [jit.streak](https://docs.cycling74.com/reference/jit.streak "jit.streak") controls the likeliness that any given cell in the matrix will be copied onto a neighboring cell. Our [jit.streak](https://docs.cycling74.com/reference/jit.streak "jit.streak") object has a `prob` attribute of `0.5`, so there's a 50% chance of this happening with any given cell. 
Technical Detail: By default, [jit.streak](https://docs.cycling74.com/reference/jit.streak "jit.streak") copies cells towards the left. Changing the `direction` attribute will alter this behavior. There is also a `scale` attribute that determines the brightness of the 'streaked' cells as compared to their original values. The help patch for [jit.streak](https://docs.cycling74.com/reference/jit.streak "jit.streak") explains more about how the object works.
![Our effects chain with intermediate  jit.pwindow  objects to show the processing](https://docs.cycling74.com/images/2898f10f75dc18989c4c520af0b9e584_251.webp) Our effects chain with intermediate jit.pwindow objects to show the processing
## Summary
Pairs of named [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") objects can be used effectively to store previous iterations of a Jitter process. These techniques can be used to generate video delay effects by combining the previous matrix with the current one using matrix compositing objects such as [jit.op](https://docs.cycling74.com/reference/jit.op "jit.op"). You can also use [jit.matrix](https://docs.cycling74.com/reference/jit.matrix "jit.matrix") objects to resample an image (using the `dim` attribute), both to perform an algorithm more efficiently (the smaller the matrix, the faster it will be processed by subsequent images) and to create pixelation effects. The [jit.streak](https://docs.cycling74.com/reference/jit.streak "jit.streak") object performs random cell streaking on an input matrix by copying cells over to their neighbors according to a probability factor (set by the `prob` attribute).

# Tutorial 21: Controlling Data Flow
## Introduction
In this tutorial, we will learn some techniques for regulating data flow within a Max patch, using the [gate](https://docs.cycling74.com/reference/gate/ "gate"), [switch](https://docs.cycling74.com/reference/switch/ "switch") and [router](https://docs.cycling74.com/reference/router/ "router") to direct events. We will also examine user interface elements that can be used to manage these controls, including the [radiogroup](https://docs.cycling74.com/reference/radiogroup/ "radiogroup") and [matrixctrl](https://docs.cycling74.com/reference/matrixctrl/ "matrixctrl") objects. These objects will be used to vary the drawing commands used for an interactive drawing routine.
Part of creating an interactive (or performance-based) Max patch is presenting options, and allowing for selection from among these options. The [gate](https://docs.cycling74.com/reference/gate/ "gate") and [switch](https://docs.cycling74.com/reference/switch/ "switch") objects control event routing from and to single data sources, while the [router](https://docs.cycling74.com/reference/router/ "router") object performs routing among a matrix of connections. All of these routing objects are far more useful once we have a way to simply and obviously control the routing – hence, we use the [radiogroup](https://docs.cycling74.com/reference/radiogroup/ "radiogroup") and [matrixctrl](https://docs.cycling74.com/reference/matrixctrl/ "matrixctrl") objects as the “visible” switching controls for the actual control objects.
## The old [gate](https://docs.cycling74.com/reference/gate/ "gate") and [switch](https://docs.cycling74.com/reference/switch/ "switch")
Take a look at the patcher for this tutorial. This is a large-ish patch that implements two drawing routines. Let’s focus on the left-hand drawing system (labeled **1**) first.
The [metro](https://docs.cycling74.com/reference/metro/ "metro") at the top of the patch fires off `bang` messages that are sent to a [patcher](https://docs.cycling74.com/reference/patcher/ "patcher") called `mousedraw`. The contents of this subpatch should look familiar – it scales the mouse movements of your screen geometry to the size of the lower-left [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object (using our previously made **WTHITM_scaled** abstraction), then describes a dimensional list +/- 6 pixels from the calculated location. This is the sort of thing that we’ve done several times in previous tutorials. The output of this subpatcher is sent into the right inlet of a [gate](https://docs.cycling74.com/reference/gate/ "gate") object, where it is sent to one of four potential [prepend](https://docs.cycling74.com/reference/prepend/ "prepend") objects. These objects determine if a square or circle will be drawn, and if it will have a frame or a filled shape.
The purpose of the [gate](https://docs.cycling74.com/reference/gate/ "gate") object is to select which of the four (if any) [prepend](https://docs.cycling74.com/reference/prepend/ "prepend") message will receive the dimension list. The input into the _left_ inlet of [gate](https://docs.cycling74.com/reference/gate/ "gate") will route the events coming into the _right_ inlet to the selected outlet; a setting of `0` will turn off output completely. Turn on the [metro](https://docs.cycling74.com/reference/metro/ "metro") using the [toggle](https://docs.cycling74.com/reference/toggle/ "toggle") object at the top. Using the [number](https://docs.cycling74.com/reference/number/ "number") box connected to the left inlet, you can choose a number between `1` and `4` to see the result in the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object’s display.
The input of the [number](https://docs.cycling74.com/reference/number/ "number") box is connected to a user interface object with five small circles; this is a [radiogroup](https://docs.cycling74.com/reference/radiogroup/ "radiogroup") object, and it is used to select a single number among a discrete set of options. If you unlock the patch and check the [radiogroup](https://docs.cycling74.com/reference/radiogroup/ "radiogroup") object’s inspector, you will see the option _Number of Items_ is set to `5`. This attribute determines the number of options provided. Returning to the patch and locking it, you can see that selecting one of the [radiogroup](https://docs.cycling74.com/reference/radiogroup/ "radiogroup") options outputs the number of the selection option, starting with `0`. This is a perfect way to control the output of [gate](https://docs.cycling74.com/reference/gate/ "gate"), and can be used for quick selection of options when doing message routing.
To the right of the [gate](https://docs.cycling74.com/reference/gate/ "gate") -based drawing routine is a similar system based around a [switch](https://docs.cycling74.com/reference/switch/ "switch") object. Stop the mouse drawing by setting the left [radiogroup](https://docs.cycling74.com/reference/radiogroup/ "radiogroup") object to `0` - (the top selection) and clear the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object by hitting the space bar. Once the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") is cleared, select one of the non-zero [radiogroup](https://docs.cycling74.com/reference/radiogroup/ "radiogroup") options connected to the [switch](https://docs.cycling74.com/reference/switch/ "switch") object. You will see a random-based automated drawing routine laying in circles on the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object. Option `1` uses a drawing routine based on the [drunk](https://docs.cycling74.com/reference/drunk/ "drunk") object, while option `2` uses a routine based on the [random](https://docs.cycling74.com/reference/random/ "random") object. If you want to stop the automated drawing, you can select the `0` option, and nothing is sent to the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object.
The [switch](https://docs.cycling74.com/reference/switch/ "switch") object is the inverse of the [gate](https://docs.cycling74.com/reference/gate/ "gate") object; where the [gate](https://docs.cycling74.com/reference/gate/ "gate") object routes one input into many outlets, the [switch](https://docs.cycling74.com/reference/switch/ "switch") object is used to choose the routing of many inputs into one output. In this case, both of the [patcher](https://docs.cycling74.com/reference/patcher/ "patcher") objects are producing output messages, but only one subpatcher will have its messages sent to the [prepend](https://docs.cycling74.com/reference/prepend/ "prepend") object. As with the [gate](https://docs.cycling74.com/reference/gate/ "gate") object, the selection is controlled by the value sent to the left-hand input, and a value of `0` will prevent any messages from passing through the [switch](https://docs.cycling74.com/reference/switch/ "switch").
## Using [router](https://docs.cycling74.com/reference/router/ "router")
In some cases, you need to route many inputs into many outputs – and potentially all of them simultaneously. The drawing patch **2** on the right hand side features a [metro](https://docs.cycling74.com/reference/metro/ "metro") connected to three drawing [patcher](https://docs.cycling74.com/reference/patcher/ "patcher") objects - the same three subpatchers from patch **1** , in fact. They are connected to the three right-hand inputs of the [router](https://docs.cycling74.com/reference/router/ "router") object. There are five outputs from [router](https://docs.cycling74.com/reference/router/ "router") object, the first four of which are attached to the familiar [prepend](https://docs.cycling74.com/reference/prepend/ "prepend") objects that determine the drawing shape to be used. The number of inlets and outlets are determined by the _arguments_ used to instantiate the [router](https://docs.cycling74.com/reference/router/ "router") object. The key to making this patch operate is the grid-shaped user interface object connected to the leftmost inlet of [router](https://docs.cycling74.com/reference/router/ "router") - this is the [matrixctrl](https://docs.cycling74.com/reference/matrixctrl/ "matrixctrl") object, and it allows us to specify a two-dimensional "grid" of connections using a message format understood by the [router](https://docs.cycling74.com/reference/router/ "router") object.
The [matrixctrl](https://docs.cycling74.com/reference/matrixctrl/ "matrixctrl") grid has three _vertical_ lines that correspond to the three _inputs_ of [router](https://docs.cycling74.com/reference/router/ "router") and four _horizontal_ lines that correspond to the four _outputs_. If you click on the intersection of two lines, a small “puck” is displayed, implying that a connection has been made. So, for example, clicking on the top-left intersection “connects” the leftmost input to the leftmost output, causing the **mousedraw**[patcher](https://docs.cycling74.com/reference/patcher/ "patcher") to produce framed rectangles when the [metro](https://docs.cycling74.com/reference/metro/ "metro") is turned on.
Turn on the [metro](https://docs.cycling74.com/reference/metro/ "metro") with the [toggle](https://docs.cycling74.com/reference/toggle/ "toggle") labeled **2** and experiment with setting and unsetting different connections in the [matrixctrl](https://docs.cycling74.com/reference/matrixctrl/ "matrixctrl") object. Notice that one major difference between [router](https://docs.cycling74.com/reference/router/ "router") and [gate](https://docs.cycling74.com/reference/gate/ "gate") or [switch](https://docs.cycling74.com/reference/switch/ "switch") is the ability to _simultaneously_ route several inputs to several outputs. Select the top-center connection, and you will see the drunken painting of framed rectangles. Now, select the connection in the middle of the second row – the painted rectangle has a circle inside of it. You may need to clear the [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") (via the space bar) to see it more clearly. Try different combinations of input and output connections to see how the matrix selection affects the painting process.
If you look in the **Max** window, you can see how the [matrixctrl](https://docs.cycling74.com/reference/matrixctrl/ "matrixctrl") passes messages to the [router](https://docs.cycling74.com/reference/router/ "router"). The objects communicate using the system of `inlet`, `outlet`, `state`, where a state of `1` makes a connection and `0` breaks the connection. Unlike [gate](https://docs.cycling74.com/reference/gate/ "gate") and [switch](https://docs.cycling74.com/reference/switch/ "switch"), the input and output numbering begins at `0`, not `1` : a connection between the left inlet and the last outlet in our example, therefore, would be set by sending the message `0 3 1` to the [router](https://docs.cycling74.com/reference/router/ "router").
## Summary
In this tutorial, we have seen a number of useful objects for routing messages within a subset of the logic in a patcher. The [switch](https://docs.cycling74.com/reference/switch/ "switch") object selects from several inputs, based on the value sent to its left inlet. The [gate](https://docs.cycling74.com/reference/gate/ "gate") is [switch](https://docs.cycling74.com/reference/switch/ "switch") ’s inverse – it will take a single input and route it to one of several outlets. If you need more complicated “matrix-like” routing, the [router](https://docs.cycling74.com/reference/router/ "router") object can pass messages arriving at multiple inlets into any (or all) of a set of outlets.
The [radiogroup](https://docs.cycling74.com/reference/radiogroup/ "radiogroup") object allows for a visual interface to objects like [gate](https://docs.cycling74.com/reference/gate/ "gate") and [switch](https://docs.cycling74.com/reference/switch/ "switch"). The [matrixctrl](https://docs.cycling74.com/reference/matrixctrl/ "matrixctrl") object provides a visual interface for matrix-style routing. The combination of [router](https://docs.cycling74.com/reference/router/ "router") and [matrixctrl](https://docs.cycling74.com/reference/matrixctrl/ "matrixctrl") provides one of the most flexible (and useful) message routing systems available in Max.

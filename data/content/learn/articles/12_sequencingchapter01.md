# Sequencing Tutorial 1: Audio-Rate Sequencing
## Introduction
This tutorial looks at how to generate timed events in Max using MSP audio signals as the synchronization source. When designing timing-based systems in Max, we're used to using [metro](https://docs.cycling74.com/reference/metro/ "metro"), [clocker](https://docs.cycling74.com/reference/clocker/ "clocker"), [delay](https://docs.cycling74.com/reference/delay/ "delay"), and other Max objects that run in the Max scheduler to generate events automatically. However, when working with MSP, it's often beneficial to be able to synchronize events directly off of an MSP signal. This technique not only allows for more precise control of event timing (so-called _sample accurate_ sequencing), but also allows us to use a number of MSP objects that allow for the synchronization of multiple event streams based on a single clock signal. Our first tutorial looks at a few of these objects and how they work.
## Providing a synchronization clock signal
  * Take a look at the tutorial patcher. Turn on audio in the patcher by clicking on the [ezdac~](https://docs.cycling74.com/reference/ezdac~/ "ezdac~") object at the top of the patch. The [scope~](https://docs.cycling74.com/reference/scope~/ "scope~") objects, as well as the [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") object in the middle of the patcher, should all spring to life. In the area of the patcher labeled `1`, click the [button](https://docs.cycling74.com/reference/button/ "button") object a few times at a steady speed. Notice how the signal scopes change, and how the [number](https://docs.cycling74.com/reference/number/ "number") box labeled `BPM` adjusts itself.


The MSP object driving the behavior in our tutorial patcher is called [sync~](https://docs.cycling74.com/reference/sync~/ "sync~"), and outputs the same kind of signal as a [phasor~](https://docs.cycling74.com/reference/phasor~/ "phasor~") object, i.e. a linear signal ramp going from `0.` to `1.` at a steady rate. Unlike the [phasor~](https://docs.cycling74.com/reference/phasor~/ "phasor~") object, however, the object understands its speed not in Hertz, but in _beats-per-minute_ (BPM), a standard definition of musical _tempo_ used in most audio sequencing applications. Clicking the [button](https://docs.cycling74.com/reference/button/ "button") object at the top of the patcher sends `bang` messages to the [sync~](https://docs.cycling74.com/reference/sync~/ "sync~") object, which simulates a _tap tempo_ system used in many sequencers. By clicking the [button](https://docs.cycling74.com/reference/button/ "button") at a steady rate, the [sync~](https://docs.cycling74.com/reference/sync~/ "sync~") object adjusts its speed to send out a single ramp for every beat (interval) between the `bang` messages. The BPM of our `bang` messages is calculated and sent out the second outlet of the [sync~](https://docs.cycling74.com/reference/sync~/ "sync~") object, which we then use to set a [number](https://docs.cycling74.com/reference/number/ "number") box that we can change to set the BPM manually.
  * In the [number](https://docs.cycling74.com/reference/number/ "number") box at the top of the patcher, type `60.` and press return. The [sync~](https://docs.cycling74.com/reference/sync~/ "sync~") object now runs at 60 BPM, outputting a signal ramp once per second. In the patcher area labeled `2` (colored green), turn up the left [gain~](https://docs.cycling74.com/reference/gain~/ "gain~") slider and listen to the result.


The output of the [sync~](https://docs.cycling74.com/reference/sync~/ "sync~") object is a signal ramp, just like the output of the [phasor~](https://docs.cycling74.com/reference/phasor~/ "phasor~") object. As such, we can use it as an envelope generator directly, to control the volume of an audio signal going to the [dac~](https://docs.cycling74.com/reference/dac~/ "dac~") (in this case, a [rand~](https://docs.cycling74.com/reference/rand~/ "rand~") noise generator). While this is certainly useful in certain applications, the main advantage of using a signal to provide event synchronization is in our ability to time-scale the signal and then generate events from it.
## Many rates at once
  * Notice that, throughout the tutorial patcher, each of the [scope~](https://docs.cycling74.com/reference/scope~/ "scope~") objects seem to be drawing ramps at different speeds:

![](https://docs.cycling74.com/images/351b334ed0014f107b8d97772e33a105_455.webp)
_Different ramp time-scales generated by use of the[sync~](https://docs.cycling74.com/reference/sync~/ "sync~")and [rate~](https://docs.cycling74.com/reference/rate~/ "rate~") objects._
The [rate~](https://docs.cycling74.com/reference/rate~/ "rate~") object allows us to _time-scale_ the ramp signals generated by [sync~](https://docs.cycling74.com/reference/sync~/ "sync~") and [phasor~](https://docs.cycling74.com/reference/phasor~/ "phasor~") objects. The argument to the object (or a new value provided in the right inlet) sets the scaling factor, e.g. a [rate~](https://docs.cycling74.com/reference/rate~/ "rate~") object with a factor of `2.0` will generate a ramp that takes _twice as long_ to repeat as the input signal. A [rate~](https://docs.cycling74.com/reference/rate~/ "rate~") of `0.5`, by comparison, will go _two times as fast_ as the input. Using this system, we can have multiple areas of signal logic in our MSP patcher running at different multiples of the original synchronization signal yet staying perfectly in time.
## Generating Max events from a synchronization signal
  * In patcher area `2`, turn down the left [gain~](https://docs.cycling74.com/reference/gain~/ "gain~") slider and turn up the right one. You should hear a regular metronomic 'click', generated by the [noise~](https://docs.cycling74.com/reference/noise~/ "noise~") object with an envelope triggered by the [button](https://docs.cycling74.com/reference/button/ "button") object in that part of the patcher.


Two things are going on here of note. The first is that the 'click' is happening not at the speed we've set in the [sync~](https://docs.cycling74.com/reference/sync~/ "sync~") object, but at four times that speed. This is the doing of the [rate~](https://docs.cycling74.com/reference/rate~/ "rate~") object in patcher area `2`, which is set to a value of `0.25`. This means that our effective musical timing for one 'beat' in our patcher is subdivided into four in this part of the MSP signal chain, allowing us to trigger faster events.
The 'click' we hear is generated by sending a `bang` message (from the [button](https://docs.cycling74.com/reference/button/ "button") object to generate an envelope from the [line~](https://docs.cycling74.com/reference/line~/ "line~") object, fading in and out the [noise~](https://docs.cycling74.com/reference/noise~/ "noise~") quickly to make a sharp ticking sound. This logic is familiar to use from previous tutorials; the big question here is, how is the [button](https://docs.cycling74.com/reference/button/ "button") object being triggered?
The MSP [delta~](https://docs.cycling74.com/reference/delta~/ "delta~") object takes a signal input and outputs a signal, the numbers of which report how much the incoming signal has _changed_ from sample to sample:
![](https://docs.cycling74.com/images/a3649cf81f0bad18d5e4535042f99340_323.webp)
_A[phasor~](https://docs.cycling74.com/reference/phasor~/ "phasor~") ramp (top) and its [delta~](https://docs.cycling74.com/reference/delta~/ "delta~") signal (bottom)._
In the case of a ramp signal, the [delta~](https://docs.cycling74.com/reference/delta~/ "delta~") object reports a more-or-less constant positive value as the signal rises; when the ramp resets to `0.`, however, the [delta~](https://docs.cycling74.com/reference/delta~/ "delta~") object reports a sudden, high, _negative_ value that represents the sudden drop in the ramp. This momentary negative signal value can be detected by using a logical operator on the signal to test whether it goes negative. The [<~](https://docs.cycling74.com/reference/%3C~/ "<~") object in the patcher does this, by outputting a signal value of `1` when the input signal matches the condition specified by the object's argument, and a `0` otherwise. In the present case, the output of [<~](https://docs.cycling74.com/reference/%3C~/ "<~") will be a `1` whenever the input signal is _less than_`0` , i.e. only when the ramp coming out of the [rate~](https://docs.cycling74.com/reference/rate~/ "rate~") object resets, causing the [delta~](https://docs.cycling74.com/reference/delta~/ "delta~") object to output a negative value.
The [edge~](https://docs.cycling74.com/reference/edge~/ "edge~") object is an MSP object that takes input signals and uses them to trigger Max `bang` messages. It does this by looking at transition states from `0` to `1` (left outlet) or `1` to `0` (right outlet). When the [rate~](https://docs.cycling74.com/reference/rate~/ "rate~") object resets its ramp, the left outlet of the [edge~](https://docs.cycling74.com/reference/edge~/ "edge~") object generates a `bang` in response to the logical `0` to `1` (false to true) transition coming out of the [<~](https://docs.cycling74.com/reference/%3C~/ "<~") object. This `bang` can trigger any Max event, just as if it were fired from a [metro](https://docs.cycling74.com/reference/metro/ "metro") object or triggered by clicking a [button](https://docs.cycling74.com/reference/button/ "button") manually.
  * Turn down the [gain~](https://docs.cycling74.com/reference/gain~/ "gain~") slider at the bottom of patcher area `2` and take a look at patcher area `3`.


## Audio-rate sequencing using fixed timing intervals
  * In patcher area `3`, click and draw in the two [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") objects labeled 'Pitch' and 'Amplitude'. Turn up the [gain~](https://docs.cycling74.com/reference/gain~/ "gain~") slider at the bottom of patcher area `3` 's logic. You should hear a square wave repeating a melodic pattern that matches the shape you drew in the [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") objects. Try drawing different patterns for the sequence and listen to the results.


The repeating melody specified by our [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") objects is being triggered by a sample-accurate sequencing object called [techno~](https://docs.cycling74.com/reference/techno~/ "techno~"). The [techno~](https://docs.cycling74.com/reference/techno~/ "techno~") object maintains a certain number of _steps_ of data points based on its `length` parameter (set in our tutorial patcher with the message `length 16`). Each step can have a pitch and amplitude associated with it, which it then puts out as _signals_ from its outlets. These signals contain all the information necessary to directly drive MSP oscillators and amplifiers (in this case the [rect~](https://docs.cycling74.com/reference/rect~/ "rect~") and [*~](https://docs.cycling74.com/reference/*~/ "*~") objects).
Sequences are loaded into the [techno~](https://docs.cycling74.com/reference/techno~/ "techno~") object by sending `pitch` and `amplitude` messages with the step number and value as their arguments. The [listfunnel](https://docs.cycling74.com/reference/listfunnel/ "listfunnel") objects in our tutorial patcher create the appropriate messages for this purpose, by taking the sixteen-member lists from the [multislider](https://docs.cycling74.com/reference/multislider/ "multislider") objects and translating them into sixteen individual, numbered messages. By a similar token, other attributes of the sequence process can be set, either for each step individually or for the entire sequence.
  * At the bottom of patcher area `3`, set the [number](https://docs.cycling74.com/reference/number/ "number") box labeled 'Attack' to `1.0`. Notice how the notes change from being short to long (or _staccato_ to _legato_). Set the [number](https://docs.cycling74.com/reference/number/ "number") box labeled 'Decay' to `0.`. Notice how the envelope of the notes change to produce a different kind of note separation where the square wave fades in and ends abruptly. Set both the 'Attack' and 'Decay' values to `1.` and change the [number](https://docs.cycling74.com/reference/number/ "number") box labeled 'Curve' to `0.1`. Hear how the pitches now slide into on another.


The `attack`, `decay`, and `curve` messages, like the `pitch` and `amplitude` messages, allow us to fine-tune the behavior of the internal sequencer of the [techno~](https://docs.cycling74.com/reference/techno~/ "techno~") object. The `attack` values control the trajectory for the envelope coming out of the middle outlet of the [techno~](https://docs.cycling74.com/reference/techno~/ "techno~") object as it rises at the beginning of a note. A value of `0` causes the notes to snap on instantaneously; a value of `1.0` causes the tones in the sequence to take the entire beat to fade in from their previous value. The `decay` values work on a similar principle, only with regards to the end (or 'release' stage) of the note's envelope. A `decay` of 1.0 allows the notes to blend together; a value of `0` ensures that each note falls to silence between steps of the sequencer. These two values interact to create dynamic envelope shapes. the `curve` messages control the amount of _portamento_ (or gliding) applied to the signal controlling the sequence's _pitch_. Curve values of `0` will cause the pitches to 'snap' from note to note in the sequence. As we raise the `curve` value, more and more of the beat will be taken up by an interpolating pitch ramp, causing the sound to slide around in frequency.
As with the `pitch` and `amplitude`, the `attack`, `decay`, and `curve` parameters of the [techno~](https://docs.cycling74.com/reference/techno~/ "techno~") object are provided on a _step-by-step_ basis. Notice how we use the [uzi](https://docs.cycling74.com/reference/uzi/ "uzi") object to transmit the same value sixteen times to set every step of our sequence to the same values.
  * Play around with the possibilities of sequencing with [techno~](https://docs.cycling74.com/reference/techno~/ "techno~"). Once you've gotten a grasp of how the controls work, turn down the [gain~](https://docs.cycling74.com/reference/gain~/ "gain~") slider for patcher area `3` and take a look to the right, at patcher area `4`.


## Audio-rate sequencing of arbitrary data
  * Turn up the [gain~](https://docs.cycling74.com/reference/gain~/ "gain~") slider for patcher area `4`. Using your computer keyboard, type on the middle row of letter keys (A, S, D, F, G, H, J, K, L, ;). You should hear different notes being played from a simple sawtooth oscillator. If you like, double-click the [coll](https://docs.cycling74.com/reference/coll/ "coll") object named `keys` to see the mapping from ASCII values to MIDI note numbers.
  * Click the 'r' key on your keyboard and play some notes on the middle row. Notice that the [toggle](https://docs.cycling74.com/reference/toggle/ "toggle") object attached to the `record $1` message becomes enabled. Click the 'r' key a second time, and click the 'p' key. Once the sequence repeats, you should hear your notes played back.


The [seq~](https://docs.cycling74.com/reference/seq~/ "seq~") object works as an audio-rate sequencer of arbitrary numeric events. The signal it receives in its input serves as a synchronization clock for the object, allowing us to feed it with a signal ramp from a [rate~](https://docs.cycling74.com/reference/rate~/ "rate~") object set to eight measures. When [seq~](https://docs.cycling74.com/reference/seq~/ "seq~") receives a `record 1` message, it listens to Max messages coming into the object and _timestamps_ them based on the input signal. When [seq~](https://docs.cycling74.com/reference/seq~/ "seq~") is in 'play' mode (through a `play 1` message), it uses the input signal to look up events based on their timestamp, and outputs them in the correct order. Note that, unlike the [techno~](https://docs.cycling74.com/reference/techno~/ "techno~") object, the [seq~](https://docs.cycling74.com/reference/seq~/ "seq~") object outputs Max events, not signal values, and so it can be used to store arbitrary data.
Though beyond the scope of this tutorial, the [seq~](https://docs.cycling74.com/reference/seq~/ "seq~") object can store multiple sequences simultaneously, can overdub multiple passes of data, and can read and write files of data in a manner similar to the [coll](https://docs.cycling74.com/reference/coll/ "coll") object. Also, because it stores arbitrary, timestamped messages, it can be used to sequence other Max commands besides MIDI with sample accuracy, e.g. lists of drawing commands to an [lcd](https://docs.cycling74.com/reference/lcd/ "lcd") object, or messages to a series of Jitter objects, etc. Finally, the signal providing the timestamping for the [seq~](https://docs.cycling74.com/reference/seq~/ "seq~") object can be at an arbitrary scale; it doesn't have to be in the range of `0` to `1`, nor do you have to send it a linear ramp. This further expands the flexibility of the object.
  * Turn up the lower [gain~](https://docs.cycling74.com/reference/gain~/ "gain~") slider in patcher area `1` to give yourself a click to work against. Hit the 'c' key to `clear` the sequence stored in the [seq~](https://docs.cycling74.com/reference/seq~/ "seq~") object. Hit the 'r' key to record a new sequence. When the sequence loop has wrapped around, disable recording and play your sequence. Notice that the [seq~](https://docs.cycling74.com/reference/seq~/ "seq~") object can handle data with any timing interval, unlike the [techno~](https://docs.cycling74.com/reference/techno~/ "techno~") object, which works in discrete steps.


## Summary
MSP has a variety of tools for audio-rate sequencing. The [sync~](https://docs.cycling74.com/reference/sync~/ "sync~") and [rate~](https://docs.cycling74.com/reference/rate~/ "rate~") objects can be used to create simple timing ramps and regular intervals using beats-per-minute values to determine tempo. The [delta~](https://docs.cycling74.com/reference/delta~/ "delta~") and [edge~](https://docs.cycling74.com/reference/edge~/ "edge~") objects are useful in generating Max events from an MSP ramp signal. The [techno~](https://docs.cycling74.com/reference/techno~/ "techno~") object allows for sample-accurate sequencing of a finite number of steps for a single audio oscillator/amplifier pair; for more flexible sequencing, the [seq~](https://docs.cycling74.com/reference/seq~/ "seq~") object allows for audio-rate timestamping of arbitrary Max events which can be saved, edited, and replayed as sequences of instructions.
